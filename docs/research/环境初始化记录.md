# FBA 环境初始化记录

本文件按当前这台 Linux 开发机来写，照着做就能连上库并启动三个服务。端口和启停脚本以仓库 `scripts/start_all.sh`、`scripts/stop_all.sh` 为准：脚本用自身位置定位仓库根目录，下面的命令都在仓库根目录执行，不写死家目录。

早先记录写过 macOS、Homebrew `postgresql@18` 和 FlyEnv 数据目录。那套路径在这台机器上不存在，不要照做。

## 3. 启动 / 停止 / 重启

在仓库根目录：

```bash
scripts/start_all.sh
scripts/stop_all.sh
```

PID：`.runtime/*.pid`  
日志：`.runtime/logs/`

`stop_all.sh` 只停止 pidfile 校验通过的后端、管理端和骑手 H5。它不停止 PostgreSQL / Redis。`STOP_POSTGRES=1` 会被忽略。

### 3.1 后端

在 `fastapi-best-architecture` 目录：

```bash
export LC_ALL=en_US.UTF-8 LANG=en_US.UTF-8 PYTHONUNBUFFERED=1
uv sync --group dev --python 3.12
uv run --python 3.12 fba run --no-reload
```

- 重启：先 `scripts/stop_all.sh`，再 `scripts/start_all.sh`。
- `--no-reload` 关闭文件热重载，适合后台常驻。开发改代码可去掉该参数。
- Celery worker/beat/flower 不由 `start_all.sh` 启动。未起过 worker 时，任务结果相关接口会报错。

### 3.2 前端

在 `fastapi-best-architecture-ui` 根目录：

```bash
CI=true pnpm install          # CI=true 跳过 lefthook git hook
pnpm dev:antdv-next           # 等价于 pnpm -F @vben/web-antdv-next run dev
```

骑手 H5 在 `rider-h5/`：`pnpm install` 后 `pnpm run dev`，端口 5174。`start_all.sh` 会一并拉起。

### 3.3 PostgreSQL 与 Redis

两个服务要先于 `start_all.sh` 处于监听状态。本机集群已经是 16/main，未监听时用发行版服务拉起，不要改端口，也不要去找 Homebrew 或 FlyEnv：

```bash
sudo service postgresql start
# 等价：sudo pg_ctlcluster 16 main start
sudo service redis-server start
```

连库：

```bash
PGPASSWORD=postgres psql -h 127.0.0.1 -p 5432 -U root -d fba
```

## 4. 登录接口 curl 示例

登录验证码默认开启（`LOGIN_CAPTCHA_ENABLED=true`，参数配置插件会在登录时动态覆盖）。不要改 `conf.py`。开发验证可从 Redis 取出验证码明文。

```bash
# 1) 取验证码 uuid
CAPTCHA=$(curl -sS http://127.0.0.1:8000/api/v1/auth/captcha)
UUID=$(python3 -c 'import json,sys; print(json.load(sys.stdin)["data"]["uuid"])' <<<"$CAPTCHA")
CODE=$(redis-cli GET "fba:login:captcha:$UUID")

# 2) JSON 登录拿 token
LOGIN=$(curl -sS -X POST http://127.0.0.1:8000/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d "{\"username\":\"admin\",\"password\":\"123456\",\"uuid\":\"$UUID\",\"captcha\":\"$CODE\"}")
TOKEN=$(python3 -c 'import json,sys; print(json.load(sys.stdin)["data"]["access_token"])' <<<"$LOGIN")

# 3) 受保护接口：当前用户
curl -sS http://127.0.0.1:8000/api/v1/sys/users/me \
  -H "Authorization: Bearer $TOKEN"
```

无验证码快捷通道（Swagger 调试专用，HTTP Basic）：

```bash
curl -sS -u admin:123456 -X POST http://127.0.0.1:8000/api/v1/auth/login/swagger
```

注意：`POST /api/v1/auth/login` 有速率限制（约每分钟 5 次）。

## 5. 数据库初始化 / 重置

主键模式：`autoincrement`。对应脚本文件名 **不含** `_snowflake`。

**不要在共享库上跑 `fba init`**（会 drop 全部 ORM 表）。插件表的重建见 `docs/约定/01-后端开发约定.md` §6.3：停服务 → `psql -f sql/postgresql/destroy.sql` → 启动后端（`create_all` 建表）→ `psql -f sql/postgresql/init.sql` → 依次执行 `sql/patch/*.sql`。

只补跑某一个脚本（表需为空或先执行对应 `destroy.sql`，否则主键冲突）：

```bash
cd fastapi-best-architecture
PGPASSWORD=postgres psql -h 127.0.0.1 -p 5432 -U root -d fba \
  -f backend/plugin/dict/sql/postgresql/init.sql
```

新插件 SQL 同样放在 `backend/plugin/<name>/sql/postgresql/init.sql`（自增）或 `init_snowflake.sql`（雪花）。业务表应由模型 `create_all` 创建，init.sql 只放菜单/种子。

## 7. 遇到的问题与解决办法

1. **PostgreSQL 未监听 5432**  
   `sudo service postgresql start` 或 `sudo pg_ctlcluster 16 main start`。确认 `pg_lsclusters` 里 `16/main` 为 online。不要使用 PostgreSQL 18、Homebrew 或 `~/Library/FlyEnv`。

2. **Redis 未监听 6379**  
   `sudo service redis-server start`。`scripts/start_all.sh` 检测到未监听会直接退出，不会替你拉起。

3. **连库角色不对**  
   超级用户是 `root` / 密码 `postgres`，不是 Linux 登录名。`backend/.env` 使用 `DATABASE_USER=root`、`DATABASE_PASSWORD=postgres`。

4. **`uv` 不在默认 PATH**  
   本机装在 `~/.local/bin/uv`。`start_all.sh` 会把这个目录加进 PATH。手工跑后端时同样保证能找到 `uv`。

5. **Node 低于管理端 engines**  
   脚本在 `~/.nvm/versions/node` 里改用符合 `^22.18.0` 或 `^24.0.0` 的版本。不要改脚本去写死某一个绝对路径。

6. **`fba init` 会清空 ORM 表**  
   日常重置插件不要用它。见 §5。

7. **登录验证码**  
   不能改 `conf.py`。测试从 Redis 读 `fba:login:captcha:<uuid>`，或走 `/auth/login/swagger`。

8. **登录限流**  
   `/auth/login`、`/auth/captcha` 有 pyrate-limiter，频繁 curl 会 429。

9. **`STOP_POSTGRES=1` 停不了库**  
   `stop_all.sh` 会打印已忽略，避免误停共享数据库。

## 8. 最终配置取值

- `DATABASE_TYPE=postgresql`
- `DATABASE_PK_MODE=autoincrement`
- `DATABASE_HOST=127.0.0.1` `DATABASE_PORT=5432` `DATABASE_USER=root` `DATABASE_PASSWORD=postgres`
- `DATABASE_SCHEMA=fba`
- `REDIS_HOST=127.0.0.1` `REDIS_PORT=6379` `REDIS_PASSWORD=` `REDIS_DATABASE=0`
- `ENVIRONMENT=dev`

文件：`fastapi-best-architecture/backend/.env`（由 `.env.example` 复制）。

生产部署（Nginx、备份、健康检查）见仓库根目录 `deploy/qipay/README.md`。不要用那套编排改本机 `backend/.env`，也不要占用 8000 / 5173 / 5174。
