# 骑手薪资管理平台 · 前端架构调研手册

> 调研范围：`fastapi-best-architecture-ui`（Vben Admin 5.7.0 + Antdv Next）的 `apps/web-antdv-next`。
> 开发方式：在 `apps/web-antdv-next/src/plugins/<插件名>/` 以**前端插件**落地管理后台 + 骑手端 H5。
> 本文只读调研，供后续前端开发子代理直接对照实现。路径均为仓库内绝对路径。

## 0. 给实现者的 30 秒结论

| 问题 | 结论 |
|------|------|
| 权限模式 | `accessMode: 'backend'`，**菜单与页面路由以 `sys_menu` 为准**，不是插件 `routes/index.ts` |
| 插件怎么被发现 | `import.meta.glob('../../plugins/**/routes/*.ts')` 扫路由；`../plugins/**/*.vue` 扫页面；`../plugins/**/langs/**/*.json` 扫文案。**没有 `src/plugins/index.ts`** |
| 后台列表页怎么写 | 抄 `notice`：`useVbenVxeGrid` + `useVbenForm` + `useVbenModal`/`useVbenDrawer` |
| 无国际化直接写中文 | **可行**。`langs/` 非强制，无 ESLint 强制 `$t` |
| 独立 H5（无侧边栏、URL 直开）不改框架 | **不能做到完整形态**。见第 4、11 节 |
| 图表 | 已有 `echarts`（`@vben/plugins/echarts`），无 `@vben/plots` / Vant |
| 金额格式化 | **项目内无现成工具**，用 `Intl.NumberFormat` 或 Antdv `Statistic` |

建议拆两个前端插件目录：

- `src/plugins/qipay-admin/`：管理后台（排班、方案、工资、预支、骑手账号）
- `src/plugins/qipay-rider/`：骑手 H5 页面组件（日历、工资卡、预支表单）

后台菜单走 `sys_menu`；骑手 H5 必须接受一次**最小框架改动**（见第 11 节），否则只能塞进 BasicLayout。

## 2. 插件机制

### 2.1 自动扫描位置（没有 `src/plugins/index.ts`）

三处 `import.meta.glob`：

**路由** — `apps/web-antdv-next/src/router/routes/index.ts`

```7:43:fastapi-best-architecture-ui/apps/web-antdv-next/src/router/routes/index.ts
const dynamicRouteFiles = import.meta.glob('./modules/**/*.ts', {
  eager: true,
});

const pluginRouteFiles = import.meta.glob('../../plugins/**/routes/*.ts', {
  eager: true,
});

const dynamicRoutes: RouteRecordRaw[] = mergeRouteModules(dynamicRouteFiles);
const pluginRoutes: RouteRecordRaw[] = mergeRouteModules(pluginRouteFiles);

const accessRoutes = [...dynamicRoutes, ...pluginRoutes, ...staticRoutes];
```

`mergeRouteModules` 只收每个文件的 `export default routes` 数组。

**页面组件映射（后端菜单 `component` → `.vue`）** — 同一文件 + `src/router/access.ts`：

```17:21:fastapi-best-architecture-ui/apps/web-antdv-next/src/router/access.ts
  const pageMap: ComponentRecordType = {
    ...import.meta.glob('../views/**/*.vue'),
    ...import.meta.glob('../plugins/**/*.vue'),
  };
```

**文案** — `apps/web-antdv-next/src/locales/index.ts`

```22:34:fastapi-best-architecture-ui/apps/web-antdv-next/src/locales/index.ts
const modules = import.meta.glob('./langs/**/*.json');
const pluginModules = import.meta.glob('../plugins/**/langs/**/*.json');
const pluginLocalesMap = loadLocalesMapFromDir(
```

JSON 文件名会变成 i18n 的一级 key。例如 `langs/zh-CN/notice.json` → `$t('notice.xxx')`。

### 2.2 `plugin.toml` 的作用

每个前端插件必须有，但 **web-antdv-next 运行时不解析它**（全库搜不到 `plugin.toml` 读取代码）。用途：

- 约定/市场元数据（`summary` / `version` / `description` / `author` / `tags`）
- 文档要求的必填文件

样例（notice）：

```toml
[plugin]
summary = 'Notice UI'
version = '0.0.1'
description = 'fba Notice 插件的前端实现'
author = 'wu-clan'
tags = ['other']
```

`tags` 允许：`ai` `mcp` `agent` `auth` `storage` `notification` `task` `payment` `other`。

另需一个 workspace `package.json`（pnpm workspace 包含 `apps/*/src/plugins/*`）：

```json
{
  "name": "@fba-ui/qipay-admin",
  "version": "0.0.1",
  "private": true,
  "type": "module"
}
```

email / aliyun-sms 只有 `api/` + `plugin.toml`，没有 `routes/` `views/`，说明前端插件也可以只提供 API 给别的插件 import。

### 2.3 `langs/` 是否强制？直接写中文是否可行？

**可行，langs 非强制。**

证据：

1. glob 匹配不到只是没有插件文案，不会报错。
2. ESLint 配置（`internal/lint-configs/eslint-config`）**没有** `vue-i18n` / `@intlify` 规则，不强制 `$t`。
3. 内置插件已经在表格列里直接写中文，例如 notice `data.ts`：`title: '标题'`、`label: '状态'`、`label: '内容'`。
4. vue-i18n missing handler 仅当 key **包含 `.`** 时在开发环境 `console.warn`。`$t('骑手管理')` 找不到就原样返回该字符串。
5. 侧栏会 `$t(item.name)`（`packages/effects/layouts/src/basic/layout.vue`）。`sys_menu.title` 写成中文即可显示中文；写成 `qipay.menu` 这种带点 key 才需要 langs。

建议：

- 管理后台 UI 文案直接中文。
- 若 `sys_menu.title` 也用中文，不要带 `.`。
- 不要为了「看起来规范」去调 `$t('qipay.xxx')` 却不建 langs，开发控制台会刷 missing key。

### 2.4 插件 `api/index.ts` 写法

统一：

```ts
import { requestClient } from '#/api/request';
```

`requestClient` 配置（`src/api/request.ts`）：

- `baseURL` = `VITE_GLOB_API_URL`
- `responseReturn: 'data'`：成功时拦截器取出响应 JSON 的 `data` 字段
- 成功码：`code === 200`（不是 0）
- 请求头：`Authorization: Bearer <token>`、`Accept-Language`
- 401：尝试 `/api/v1/auth/refresh`（`withCredentials: true`），失败则 `authStore.logout()`
- 业务/HTTP 错误：`message.error(...)` 自动弹出（`errorMessageResponseInterceptor`）

因此 API 函数里 **不要再解包 `.data`**，直接拿返回值：

```ts
export async function getNoticeListApi(params: SysNoticeParams) {
  return await requestClient.get<PaginationResult<SysNoticeResult>>(
    '/api/v1/sys/notices',
    { params },
  );
}
```

分页结构（`src/types/pagination.ts`）：

```ts
interface PaginationResult<T> {
  items: Array<T>;
  page: number;
  size: number;
  total: number;
  total_pages: number;
  links: any;
}
```

成功提示要自己 `message.success(...)`。失败提示拦截器已经弹过，一般不必再弹一次。

另有：

- `miniRequestClient`：无 token 拦截，给 refresh 用
- `baseRequestClient`：原始 axios，不解包

### 2.5 重要：当前 `accessMode: 'backend'` 下，插件 `routes/index.ts` **不驱动菜单**

`generateAccessible('backend')` 只走 `generateRoutesByBackend` → `GET /api/v1/sys/menus/sidebar`，**忽略** `accessRoutes` 里的插件路由。

插件 `routes/index.ts` 的实际作用：

- 文档/市场约定
- 若将来改成 `frontend` / `mixed` 才会生效
- `componentKeys` 仍会扫描所有 `plugins/**/*.vue`，菜单管理里的「页面组件」下拉能选到插件页面

**真正让页面出现在后台的是：vue 文件存在 + `sys_menu.component` 指向它。**

OAuth2 回调是例外：`guard.ts` 把 `/oauth2/callback` 写死了，不是通用插件能力。

## 3. 路由与菜单

### 3.1 前端静态还是后端 `sys_menu`？

**后端驱动。** `src/preferences.ts`：

```ts
export const overridesPreferences = defineOverridesPreferences({
  app: {
    accessMode: 'backend',
    name: import.meta.env.VITE_APP_TITLE,
    enableRefreshToken: true,
  },
  // ...
});
```

流程：

1. 登录后 `guard.ts` 调 `generateAccess({ roles, router, routes: accessRoutes })`
2. `access.ts` 里 `fetchMenuListAsync` → `getAllMenusApi()` → `GET /api/v1/sys/menus/sidebar`
3. 后端 `MenuService.get_sidebar` 按超管/角色菜单过滤，`get_vben5_tree_data` 转成 Vben5 路由树
4. `generateRoutesByBackend` 用 `pageMap` / `layoutMap` 把字符串 `component` 换成实际 vue

按钮型菜单（`type=2`）不会进 sidebar（`get_sidebar` 过滤 `type in [0,1,3,4]`）。

### 3.2 `component` 如何映射到文件

`packages/utils/src/helpers/generate-routes-backend.ts`：

```ts
function normalizeViewPath(path: string): string {
  const normalizedPath = path.replace(/^(\.\/|\.\.\/)+/, '');
  const viewPath = normalizedPath.startsWith('/')
    ? normalizedPath
    : `/${normalizedPath}`;
  return viewPath.replace(/^\/views/, '');
}
```

`pageMap` 的 glob key（相对 `access.ts`）经同样规范化后带 `.vue` 查找。

| 磁盘文件 | glob key（access.ts） | 规范化后 pageMap key | `sys_menu.component` 应填 |
|----------|----------------------|----------------------|---------------------------|
| `src/views/system/user/index.vue` | `../views/system/user/index.vue` | `/system/user/index.vue` | `/system/user/index` |
| `src/plugins/notice/views/index.vue` | `../plugins/notice/views/index.vue` | `/plugins/notice/views/index.vue` | `/plugins/notice/views/index` |

**插件页面规则：`/plugins/<插件目录名>/views/<文件不含 .vue>`。**

匹配失败会 `console.error` 并落到 `/_core/fallback/not-found.vue`。

`layoutMap` 仅 `BasicLayout`、`IFrameView`。目录菜单 `component` 为 `null` 即可。

菜单管理下拉的 `componentKeys` 算法（`routes/index.ts`）与上表一致，新建 vue 后下拉里会出现该项。

### 3.3 `path` / `name` / `meta` 约定

后端 `get_vben5_tree_data`（`backend/utils/build_tree.py`）生成：

```python
'meta': {
    'title': node['title'],
    'icon': node['icon'],
    'iframeSrc': node['link'] if node['type'] == 3 else '',
    'link': node['link'] if node['type'] == 4 else '',
    'keepAlive': node['cache'],          # 1 真 / 0 假
    'hideInMenu': not bool(node['display']),
    'menuVisibleWithForbidden': not bool(node['status']),
}
```

**不会**输出 `noBasicLayout`、`ignoreAccess`、`authority`、`order`、`hideInTab`。

对应 `sys_menu` 字段：

| 库字段 | 前端 | 说明 |
|--------|------|------|
| `title` | `meta.title` | 侧栏 `$t(title)`；中文可直接存 |
| `name` | 路由 `name` | **必填且全局唯一**，否则 `route name is required` |
| `path` | 路由 `path` | 建议绝对路径，如 `/plugins/qipay/schedule` |
| `sort` | 树排序 | 未写入 `meta.order`，但树已按 sort 排好 |
| `icon` | `meta.icon` | Iconify 名，如 `tabler:code` |
| `type` | 菜单类型 | 0 目录 / 1 菜单 / 2 按钮 / 3 内嵌 / 4 外链 |
| `component` | 页面文件 | 见上表 |
| `perms` | 按钮权限码 | 仅 type=2，如 `sys:notice:add` |
| `status` | 启用 | 0 时 `menuVisibleWithForbidden` |
| `display` | 是否显示 | 0 → `hideInMenu: true`（路由仍在，菜单没有） |
| `cache` | `keepAlive` | 1 缓存 |
| `link` | iframe/外链 | type 3/4 |
| `parent_id` | 树 | `null` = 顶层 |

Vue Router `RouteMeta` 还支持但 **后端侧栏不会下发** 的字段：`authority`、`ignoreAccess`、`noBasicLayout`、`hideInTab`、`hideInBreadcrumb`、`affixTab`、`order`、`openInNewWindow`。要这些必须改 `build_tree.py` 或改前端 `accessMode`。

### 3.4 一级目录 vs 页面菜单

现成 SQL 两种顶层写法：

**A. 顶层目录 + 子页面**（系统菜单，`backend/sql/mysql/init_test_data.sql`）

```sql
-- type=0 目录，component 为空，parent_id 为空
(4, 'page.menu.system', 'System', '/system', 1, 'eos-icons:admin', 0, null, ...)
-- type=1 页面，挂到目录下
(5, 'page.menu.sysDept', 'SysDept', '/system/dept', 1, 'mingcute:department-line', 1, '/system/dept/index', ..., 4)
```

**B. 顶层就是一个页面**（代码生成器，无父级）

```sql
insert into sys_menu (title, name, path, sort, icon, type, component, perms, status, display, cache, link, remark, parent_id, ...)
values ('code-generator.menu', 'PluginCodeGenerator', '/plugins/code-generator', 10, 'tabler:code', 1, '/plugins/code-generator/views/index', null, 1, 1, 1, '', null, null, now(), null);
```

**C. 挂到已有「系统」目录下**（notice）

```sql
set @system_menu_id = (select id from sys_menu where name = 'System');
insert into sys_menu (title, name, path, sort, icon, type, component, perms, status, display, cache, link, remark, parent_id, created_time, updated_time)
values ('notice.menu', 'PluginNotice', '/plugins/notice', 9, 'fe:notice-push', 1, '/plugins/notice/views/index', null, 1, 1, 1, '', null, @system_menu_id, now(), null);
```

有子路由时，`generateAccessible` 会给父级补 `redirect = 第一个子 path`（子 path 必须以 `/` 开头）。

## 4. 布局、独立 H5、登录与角色分流

### 4.1 默认布局

`src/router/routes/core.ts`：

- `/` → `BasicLayout`（侧栏 + 顶栏 + Tab），`redirect` 到 `preferences.app.defaultHomePath`（默认 `/analytics`）
- `/auth/*` → `AuthPageLayout`（登录壳）
- `/:path(.*)*` → 404

登录页路径常量：`LOGIN_PATH = '/auth/login'`（`packages/constants/src/core.ts`）。

`AuthPageLayout` 实现：`src/layouts/auth.vue` 包一层 `@vben/layouts` 的 `AuthPageLayout`。

### 4.2 不使用 BasicLayout 的官方机制

`packages/effects/access/src/accessible.ts`：

```ts
accessibleRoutes.forEach((route) => {
  if (root && !route.meta?.noBasicLayout) {
    // 塞进 Root（BasicLayout）的 children
    root.children?.push(route);
  } else {
    router.addRoute(route); // 顶级独立路由
  }
});
```

`meta.ignoreAccess === true`：无 token 也可访问（`src/router/guard.ts`）。

`coreRouteNames` 里的路由（仅 `core.ts` 里那棵树）不做权限拦截。

注释掉的 `externalRoutes`：

```ts
// const externalRouteFiles = import.meta.glob('./external/**/*.ts', { eager: true });
const externalRoutes: RouteRecordRaw[] = [];
```

注释写明：外部路由可以不要 Layout，用于内嵌，不进菜单。它们会进初始 `routes`，因此 **URL 可在登录前匹配到**。但当前是空数组，且 **不在 `coreRouteNames` 里**，无 token 时仍要自己加 `meta.ignoreAccess`。

### 4.3 无 token 访问受保护路由

`src/router/guard.ts` → `setupAccessGuard`：

1. 特判 OAuth2 回调
2. `coreRouteNames`：直接放行；若已登录还访问 `/auth/login`，跳 `redirect` 或 `userInfo.homePath` 或 `defaultHomePath`
3. 无 `accessToken`：
   - `to.meta.ignoreAccess` → 放行
   - 否则跳 `/auth/login?redirect=<原 URL>`
4. 有 token 且尚未 `isAccessChecked`：拉用户信息 + `generateAccess`，再重定向

**关键：插件路由不在初始 router 表里。** 未登录访问 `/qipay/rider` 会命中 404 fallback（不在 coreRouteNames，也没有 ignoreAccess）→ 被拉去登录。登录后若 sidebar 里没有该路由，仍 404。

### 4.4 独立骑手登录页能否复用 auth store / api？

可以复用，不必重写 token 逻辑：

| 能力 | 位置 |
|------|------|
| 登录 | `useAuthStore().authLogin(params)` → `POST /api/v1/auth/login` |
| 验证码 | `useAuthStore().captcha()` → `GET /api/v1/auth/captcha` |
| 用户信息 | `GET /api/v1/sys/users/me`，`roles` 已是 **角色名称字符串数组** |
| 权限码 | `GET /api/v1/auth/codes` → `accessStore.accessCodes` |
| token | `accessStore.accessToken` + `accessSessionUuid`，pinia persist |
| 刷新 | `enableRefreshToken: true`，`POST /api/v1/auth/refresh`（cookie） |
| 登出 | `useAuthStore().logout()` |

现成登录页：`src/views/_core/authentication/login.vue`，表单字段 `username` / `password` / `uuid` / `captcha`，调 `authStore.authLogin`。

自建骑手登录页：同样调 `authLogin`，在 `onSuccess` 里 `router.push('/h5/...')`。

**但是**：这个页面本身必须已经挂在初始路由上（`coreRoutes` 或启用后的 `externalRoutes`），否则没 token 进不去。把登录 vue 只放在插件 `views/` 而不改 `core.ts` / `external`，守卫会先把人送去 `/auth/login`。

### 4.5 骑手只进 H5、管理员进后台

现状缺口：

1. 后端 `/api/v1/sys/users/me`（`GetCurrentUserInfoWithRelationDetail`）**没有 `homePath` 字段**。前端类型 `UserInfo.homePath` 是 Vben 预留，接口不会填。
2. 登录成功默认：`router.push(userInfo.homePath || preferences.app.defaultHomePath)` → 几乎总是 `/analytics`。
3. `meta.authority` 只在 `accessMode: 'frontend'|'mixed'` 的前端路由过滤里生效；当前 backend 模式看的是角色绑定的 `sys_menu`。
4. 按钮级：`accessCodes` 来自菜单 `perms`。

推荐分工（不改 packages 的前提下）：

| 目标 | 做法 |
|------|------|
| 管理员看不到 H5 菜单 | H5 菜单 `display=0`，或不把该菜单赋给管理员 |
| 骑手看不到后台 | 骑手角色只绑定 H5 相关菜单（以及可能需要的个人中心）。不要给 System/Dashboard |
| 登录后跳不同首页 | **必须**二选一：后端 `/me` 增加 `homePath`；或改 `src/store/auth.ts` 按 `userInfo.roles` 分支 `router.push` |
| 骑手打开后台 URL | 因菜单未分配，`generateRoutesByBackend` 不会注册该路由 → 404/空白。可再在页面 `onMounted` 用 `hasAccessByRoles` 兜底 |

`hasAccessByRoles` / `hasAccessByCodes` 在 backend 模式下仍可用（读 pinia），只是**路由生成阶段**不用它们。

角色名就是 `sys_role.name`（例如 `admin`、`rider`），不是 id。

### 4.6 「独立 H5 不改框架」的明确答案

**不能。** 完整形态 = URL 直开 + 移动端布局 + 无侧栏/顶栏/Tab + 可未登录进登录页。卡点同时成立：

1. `accessMode: 'backend'` 不会把插件 `routes/index.ts` 注册进 router。
2. `ignoreAccess` 只对**已经匹配到的路由**有效；插件路由登录前不存在。
3. `get_vben5_tree_data` 不下发 `noBasicLayout`，后端菜单进来的页面一律进 BasicLayout。
4. 用 `updatePreferences` 把 layout 改成 `full-content` 能藏铬，但是**全局偏好**，切回后台会乱，且仍要先登录。

不改框架的半成品：

- 登录后打开带 BasicLayout 的插件页，`display=0` 不进菜单 → **仍有侧栏**
- 页面内自己画移动端 UI，视觉上像 H5，URL 仍是后台壳

真 H5 的最小改动见第 11 节。

```vue
<script lang="ts" setup>
import type { VbenFormProps } from '@vben/common-ui';
import type { OnActionClickParams, VxeTableGridOptions } from '#/adapter/vxe-table';

import { computed, ref } from 'vue';
import { Page, useVbenDrawer, VbenButton } from '@vben/common-ui';
import { MaterialSymbolsAdd } from '@vben/icons';
import { message } from 'antdv-next';

import { useVbenForm } from '#/adapter/form';
import { useVbenVxeGrid } from '#/adapter/vxe-table';
import {
  createXxxApi,
  deleteXxxApi,
  getXxxListApi,
  updateXxxApi,
  type XxxResult,
} from '../api';
import { querySchema, schema, useColumns } from './data';

const formOptions: VbenFormProps = {
  collapsed: true,
  showCollapseButton: true,
  submitButtonOptions: { content: '查询' },
  schema: querySchema,
};

const gridOptions: VxeTableGridOptions<XxxResult> = {
  rowConfig: { keyField: 'id' },
  checkboxConfig: { highlight: true },
  height: 'auto',
  toolbarConfig: {
    refresh: true,
    refreshOptions: { code: 'query' },
    custom: true,
  },
  columns: useColumns(onActionClick),
  proxyConfig: {
    ajax: {
      query: async ({ page }, formValues) => {
        return await getXxxListApi({
          page: page.currentPage,
          size: page.pageSize,
          ...formValues,
        });
      },
    },
  },
};

const [Grid, gridApi] = useVbenVxeGrid({ formOptions, gridOptions });

function onActionClick({ code, row }: OnActionClickParams<XxxResult>) {
  if (code === 'delete') {
    deleteXxxApi([row.id]).then(() => {
      message.success({ content: `已删除 ${row.name}`, key: 'action_process_msg' });
      gridApi.query();
    });
  } else if (code === 'edit') {
    drawerApi.setData(row).open();
  }
}

const [Form, formApi] = useVbenForm({
  layout: 'vertical',
  showDefaultActions: false,
  schema,
});

const formData = ref<{ id?: number }>();
const drawerTitle = computed(() => (formData.value?.id ? '编辑' : '新增'));

const [Drawer, drawerApi] = useVbenDrawer({
  destroyOnClose: true,
  class: 'w-[480px]',
  async onConfirm() {
    const { valid } = await formApi.validate();
    if (!valid) return;
    drawerApi.lock();
    const data = await formApi.getValues();
    try {
      await (formData.value?.id
        ? updateXxxApi(formData.value.id, data)
        : createXxxApi(data));
      message.success('操作成功');
      await drawerApi.close();
      gridApi.query();
    } finally {
      drawerApi.unlock();
    }
  },
  onOpenChange(isOpen) {
    if (!isOpen) return;
    const data = drawerApi.getData<{ id?: number }>();
    formApi.resetForm();
    formData.value = data ?? undefined;
    if (data) formApi.setValues(data);
  },
});
</script>

<template>
  <Page auto-content-height>
    <Grid>
      <template #toolbar-actions>
        <VbenButton @click="() => drawerApi.setData(null).open()">
          <MaterialSymbolsAdd class="size-5" />
          新增
        </VbenButton>
      </template>
    </Grid>
    <Drawer :title="drawerTitle">
      <Form />
    </Drawer>
  </Page>
</template>
```

`data.ts` 搜索/表单 schema 直接抄 notice（`component: 'Input' | 'Select' | 'DatePicker' | 'RangePicker' | 'InputNumber'`，`rules: 'required'`）。

Antdv 原组件也可在 vue 模板里用：`<a-table>` `<a-form>` `<a-modal>` 等。后台列表优先 vxe-grid，与现有插件一致。

### 6.2 Antdv Next Calendar API

文档：`.agents/skills/antdv-next/references/components/calendar/docs.md`。

- 组件：`<a-calendar>`，`v-model:value` 为 dayjs。
- **推荐自定义格子**：插槽/属性 `fullCellRender`（整格替换）。`dateFullCellRender` 仍可用但文档标了可替代关系；`dateCellRender` **已 Deprecated**。

| 插槽 | 是否整格替换 | 备注 |
|------|--------------|------|
| `fullCellRender` | 是 | 首选 |
| `cellRender` | 否 | 官方 demo 在用 |
| `dateFullCellRender` | 是 | 旧名，仍可用 |
| `dateCellRender` | 否 | Deprecated |

**不能**靠 Calendar 自己画「跨多日横向色带」。每个 cell 是独立表格格，默认 overflow 裁剪，色带无法连到隔壁格，换行周更不行。

### 6.3 月历 + 跨多日方案色带：推荐自绘 CSS Grid

**推荐：7 列 CSS Grid 自绘月历，不要用 `a-calendar` 硬做色带。**

原因：同一方案连续区间要横向贯穿，换方案日断开换色；周边界还要切断。Grid 的「周」是一行，色带做该行的绝对定位条即可。

结构：

```
.month          display:flex; flex-direction:column
.weekdays       display:grid; grid-template-columns: repeat(7, 1fr)
.week-row       position:relative; display:grid; grid-template-columns: repeat(7, 1fr)
.day-cell       日期数字 + 点击热区；padding-top 给色带留位置
.band-layer     position:absolute; inset:0; pointer-events:none
.band           position:absolute; height:8px; border-radius:999px
```

色带算法：

1. 把当月（含补齐的上月末/下月初）打成 `weeks[][]`，每周 7 天。
2. 将排班按骑手或方案排序后，把**连续且同方案**的日期 merge 成 `[start, end]`。
3. 每个 range 再按周切开（跨周不能画一根）。
4. 周内：`left: colStart/7*100%`，`width: (colEnd-colStart+1)/7*100%`，`top` 按同日重叠条数错行。
5. 换方案：断开，换 `background`。相邻不同方案不要连。

`a-calendar` 只适合：点选日期、格子里塞 Tag/圆点。若只要「某天有排班」的标记，可用 `#cellRender` 放色块，不要做跨格色带。

管理端月历也建议同一套 Grid，桌面加宽格子即可。ECharts 热力图不能表达跨日色带。

### 7.5 权限码来源

Antdv Next 文档把静态 `message.xxx` 标成 deprecated、推荐 `message.useMessage()` / `App.useApp()`，但 **本仓库全是静态 import**，插件保持同一风格即可。

请求错误已在拦截器里 `message.error`，成功要自己弹。

### 8.4 日期

依赖 `dayjs`。项目工具：

```ts
import { formatDate, formatDateTime } from '@vben/utils';
formatDate(row.work_date);              // YYYY-MM-DD
formatDateTime(row.created_time);       // YYYY-MM-DD HH:mm:ss
```

底层 `dayjs.tz()`（`packages/@core/base/shared/src/utils/date.ts`）。表单 `DatePicker`/`RangePicker` 值是 dayjs，提交前 `.format('YYYY-MM-DD')`。

### 8.5 金额格式化：**没有现成工具**

没有 `formatMoney` / `formatAmount`。用：

```ts
new Intl.NumberFormat('zh-CN', {
  style: 'currency',
  currency: 'CNY',
}).format(12345.6); // ¥12,345.60
```

展示卡片可用 `<a-statistic :value="pay" :precision="2" prefix="¥" />`（`groupSeparator` 默认 `,`）。

## 10. 移动端

### 10.1 有没有 Vant 等？

**没有。** `package.json` / lock 中无 vant、nutui、varlet。H5 用 antdv-next + Tailwind。

### 10.2 viewport

`apps/web-antdv-next/index.html`：

```html
<meta
  name="viewport"
  content="width=device-width,initial-scale=1.0,minimum-scale=1.0,maximum-scale=1.0,user-scalable=0"
/>
```

禁止缩放，适合 App WebView / 后台，H5 也够用。改 viewport 要动 `index.html`（框架文件）。

### 10.3 断点工具

两套，都是 Tailwind `md`：

```ts
import { useIsMobile } from '@vben/hooks'; // 实际来自 @vben-core/composables
const { isMobile } = useIsMobile(); // breakpoints.smaller('md')
```

```ts
import { usePreferences } from '@vben/preferences';
const { isMobile } = usePreferences(); // preferences.app.isMobile，启动时 watch 写入
```

vxe 分页在 `isMobile` 时简化按钮。BasicLayout 在移动端变成抽屉式侧栏，**不是**去壳 H5。

### 10.4 用 antdv-next 做骑手 H5 的建议

1. **不要用 vxe-grid / Page / BasicLayout 那套。** 骑手页用 `a-card`、`a-statistic`、`a-form`、`a-button` `size="large"`、`a-list`、自绘月历。
2. 容器：`min-h-dvh max-w-md mx-auto px-4 py-3`，大屏也保持手机宽度。
3. 安全区：`pb-[env(safe-area-inset-bottom)]`。
4. 预支表单：`a-form layout="vertical"` + `a-input-number` + 底部固定提交条。
5. 工资卡：`a-statistic` 或大号 Tailwind 数字，不要桌面 Descriptions 横排。
6. 触摸：色带月历点击热区至少 44px；不要依赖 hover。
7. `message` 在移动端可用；Modal 改用 Drawer `placement="bottom"` 更像 H5。
8. 管理端日历桌面用 Grid；同一组件用 `useIsMobile` 减信息密度，不要引入第二套组件库。

Antdv 组件体积偏后台，H5 只按需引用，避免一个页面拉满 Table/Vxe。

## 11. 插件开发禁区

「只往 `src/plugins/<name>/` 丢文件、零改动 web-antdv-next 其它源码」做得到的：

- 管理后台页面（vue + api + 后端 `sys_menu`）
- 中文文案、Tailwind、Antdv、echarts（已注册类型）、vxe 列表
- 按钮权限（SQL perms + `v-access:code`）
- 登录后可访问、但仍套着 BasicLayout 的「假 H5」

### 11.1 必须改框架才能做的

| 需求 | 必须改的文件 | 不改源码的替代 |
|------|----------------|----------------|
| URL 直开、无 token 可进骑手登录页 | `src/router/routes/core.ts` 增加 `/h5/login` 子路由，或解开 `external/**/*.ts` glob 并新建 `src/router/routes/external/rider.ts`（`ignoreAccess: true`, `noBasicLayout: true`） | 复用现有 `/auth/login`，登录后再进 H5（H5 仍缺独立布局） |
| 独立布局（无侧栏） | 同上 `noBasicLayout` 的顶级路由；或改 `backend/utils/build_tree.py` 下发 `meta.noBasicLayout` | `updatePreferences({ app: { layout: 'full-content' } })` 全局藏铬，会污染管理员会话，**不推荐** |
| 登录后按角色跳 H5 / 后台 | `src/store/auth.ts` 按 `roles` 分支；或后端 `/me` 返回 `homePath` | 骑手手动输入 H5 URL；默认仍去 `/analytics` |
| 全局路由白名单 | `guard.ts` 的 `coreRouteNames` / `ignoreAccess`；或把路由放进初始 `routes` | 无 |
| 改默认首页 | `src/preferences.ts` 的 `defaultHomePath` 或后端 homePath | 无干净替代 |
| 新增 echarts 图种（如 heatmap） | `packages/effects/plugins/src/echarts/echarts.ts` | 用已有 bar/line/pie，或页面内单独 `import * as echarts`（可能重复打包） |
| 改 viewport / 标题壳 | `apps/web-antdv-next/index.html` | H5 页内自己限制 max-width |
| Vite proxy | `vite.config.ts` | 继续用 CORS + 完整 `VITE_GLOB_API_URL` |
| 允许 `127.0.0.1:5173` | 后端 `CORS_ALLOWED_ORIGINS` | 只用 `localhost:5173` |
| mixed 模式让插件 routes 生效 | `src/preferences.ts` `accessMode: 'mixed'` | 仍解决不了「登录前注册」；独立 H5 还是要进初始 `routes` |

### 11.2 骑手 H5 推荐落地（最小改动清单）

只改 web-antdv-next 应用层，不碰 `packages/`：

1. 新建 `src/router/routes/external/rider.ts`（需同时在 `routes/index.ts` **取消注释** external glob）：

```ts
import type { RouteRecordRaw } from 'vue-router';

const routes: RouteRecordRaw[] = [
  {
    name: 'QiPayRiderRoot',
    path: '/h5',
    component: () => import('#/plugins/qipay-rider/views/layout.vue'),
    meta: {
      title: '骑手端',
      hideInMenu: true,
      hideInTab: true,
      noBasicLayout: true,
    },
    children: [
      {
        name: 'QiPayRiderLogin',
        path: 'login',
        component: () => import('#/plugins/qipay-rider/views/login.vue'),
        meta: {
          title: '骑手登录',
          ignoreAccess: true,
          hideInMenu: true,
        },
      },
      {
        name: 'QiPayRiderHome',
        path: 'home',
        component: () => import('#/plugins/qipay-rider/views/home.vue'),
        meta: {
          title: '我的排班',
          hideInMenu: true,
        },
      },
    ],
  },
];
export default routes;
```

注意：`externalRoutes` 目前**不计入** `coreRouteNames`。因此：

- 登录页必须 `ignoreAccess: true`
- `noBasicLayout` 只在 `generateAccessible` 里处理；**external 已在启动时 `addRoute`，根本不会再走那段。** 只要该路由自己的 `component` 不是 BasicLayout，启动时就是独立壳。
- 受保护子路由 `/h5/home`：无 token → 守卫拉去 `/auth/login`（管理端登录）。若希望无 token 去 `/h5/login`，**必须改 `guard.ts`**（例如 `to.path.startsWith('/h5')` 时 redirect `/h5/login`）。这是第二处最小改动。

2. `src/store/auth.ts` 登录成功分支：

```ts
const roles = userInfo.roles ?? [];
const riderHome = '/h5/home';
const adminHome = userInfo.homePath || preferences.app.defaultHomePath;
await router.push(roles.includes('rider') && !roles.includes('admin') ? riderHome : adminHome);
```

3. 插件目录放 layout/login/home/日历组件；layout.vue 自己写 `min-h-dvh` 移动端壳，不要引入 `BasicLayout`。

若坚持「插件目录外零改动」：骑手先走 `/auth/login`，再手动打开仍带侧栏的插件页。产品形态不成立。

### 11.3 不要改的目录（本任务约束）

调研阶段已遵守。实现阶段：

- 尽量不改 `packages/`、`internal/`
- 管理后台可以 **只改 `src/plugins/` + 后端 SQL**
- 真 H5 允许的最小切口：`src/router/routes/index.ts`（解开 external）、`src/router/routes/external/rider.ts`、`src/router/guard.ts`（H5 登录跳转）、`src/store/auth.ts`（角色首页）
