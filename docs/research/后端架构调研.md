## 1. 应用级插件加载机制

### 1.1 发现插件

入口：`backend/plugin/core.py`。

发现条件：**`backend/plugin/<name>/` 是目录，且含 `__init__.py`**。没有 `plugin.toml` 会在 `load_plugin_config` 时抛 `PluginInjectError`。

```python
# backend/plugin/core.py
@lru_cache(maxsize=128)
def get_plugins() -> tuple[str, ...]:
    plugin_packages = []
    for item in os.listdir(PLUGIN_DIR):
        item_path = PLUGIN_DIR / item
        if os.path.isdir(item_path) and '__init__.py' in os.listdir(item_path):
            plugin_packages.append(item)
    return tuple(plugin_packages)
```

`PLUGIN_DIR` 定义于 `backend/core/path_conf.py`：`PLUGIN_DIR = BASE_PATH / 'plugin'`，即 `backend/plugin`。

级别判定（`backend/plugin/validator.py` → `validate_plugin_config`）：

| 条件 | 级别 |
|------|------|
| 配置含顶层 `api` | 扩展级 `PluginLevelType.extend` |
| 含 `app` 且无 `api` | 应用级 `PluginLevelType.app` |
| 两者都无 | 能力型 `PluginLevelType.capability` |

应用级校验模型：`AppPluginConfigSchema`，强制 `[app].router` 非空字符串列表。含 `model/` 目录时必须声明 `plugin.database`，且至少一种数据库提供齐 4 个 SQL 文件：

```text
sql/<mysql|postgresql>/init.sql
sql/<mysql|postgresql>/destroy.sql
sql/<mysql|postgresql>/init_snowflake.sql
sql/<mysql|postgresql>/destroy_snowflake.sql
```

`tags` 只允许：`ai` / `mcp` / `agent` / `auth` / `storage` / `notification` / `task` / `payment` / `other`。  
`version` 必须 `x.y.z`。`[settings]` 键必须全大写，值只能是 str / int / float / bool / `list[str]`。

### 1.2 解析配置、依赖排序、缓存

`parse_plugin_config()`：

1. `get_plugins()` 列出全部插件。
2. 独立 Redis 连接，按 `PLUGIN_REDIS_PREFIX`（默认 `fba:plugin`）清理未知 key。
3. 读 `plugin.toml`，`validate_plugin_config`。
4. 把 `plugin.name`、`plugin.enable` 写入配置后 **`SET fba:plugin:<name>`**（JSON）。
5. 按级别分成 `extend_plugins` / `app_plugins`（`PluginEntry`）。
6. 删除 `fba:plugin:changed`。

`resolve_plugin_order()` 按 `plugin.depends_on` DFS 拓扑排序，检测自依赖和环。

`get_ordered_enabled_plugins()`：**仅已启用**的扩展级+应用级，再排序。用于 hooks。能力型不注入路由。

### 1.3 注入路由

`backend/plugin/router.py` → `build_final_router()`：

1. `parse_plugin_config()` + `resolve_plugin_order()`（**不按 enable 过滤**，禁用插件的路由仍会挂上）。
2. 先注入扩展级：把插件 `api/**/*.py` 的 `router` `include_router` 到目标 app 对应路径，并加 `Depends(PluginStatusChecker(plugin.name))`。
3. **然后**才 `from backend.app.router import router as main_router`（保证扩展级先挂到 `admin` 等子路由上）。
4. 再注入应用级：从 `backend.plugin.<name>.api.router` 取 `plugin.toml` 声明的路由器实例名（通常 `v1`），`include_router` 到 `main_router`，同样挂 `PluginStatusChecker`。

应用级注入签名：

```python
# backend/plugin/router.py
def inject_app_router(plugin: PluginEntry, target_router: APIRouter) -> None:
    module_path = f'backend.plugin.{plugin.name}.api.router'
    module = import_module_cached(module_path)
    for router in plugin.routers:  # 来自 [app].router
        plugin_router = getattr(module, router, None)
        target_router.include_router(
            plugin_router,
            dependencies=[Depends(PluginStatusChecker(plugin.name))],
        )
```

启动注册：`backend/core/registrar.py` 的 `register_router` 调用 `build_final_router()`，再 `app.include_router(router)`。**主路由本身没有额外前缀**。

### 1.6 执行 SQL（安装 / 初始化 / 卸载）

`backend/plugin/sql.py`：

```python
def build_sql_filename(prefix: str, pk_type: PrimaryKeyType, *, suffix: str | None = None) -> str:
    parts = [prefix]
    if pk_type == PrimaryKeyType.snowflake:
        parts.append('snowflake')
    if suffix:
        parts.append(suffix)
    return f'{"_".join(parts)}.sql'

async def get_plugin_sql(plugin: str, db_type: DataBaseType, pk_type: PrimaryKeyType) -> str | None:
    sql_dir = PLUGIN_DIR / plugin / 'sql' / ('mysql' if db_type == DataBaseType.mysql else 'postgresql')
    default_filename = build_sql_filename('init', pk_type)  # init.sql 或 init_snowflake.sql
    ...
```

触发时机：

1. **`fba init` / `fba init --auto`**：`cli.get_sql_scripts()` 先跑主库 `backend/sql/<db>/init[_snowflake]_test_data.sql`，再按 `depends_on` 顺序跑每个插件的 init SQL。此前会 `drop_all` + `create_all`（含已导入的插件模型）。
2. **`fba add --path/--repo-url`**：安装 ZIP/Git 后 `import backend.plugin.<name>.model`，再 `create_all`，再执行该插件 init SQL（`--no-sql` 可跳过）。
3. **`fba remove <plugin>`**：先跑 `destroy.sql` / `destroy_snowflake.sql`，再备份 zip 并删目录。
4. **`fba --sql PATH`**：任意 SQL 在事务中执行。

`installer.py` 安装时还会：追加 `.env.example` 到 `backend/.env`；`uv pip install -r requirements.txt`；`SET fba:plugin:changed = true`。**安装器本身不执行 SQL**，SQL 由 CLI `Add` 负责。管理端 ZIP/Git 安装（`plugin_service.install`）同样不执行 SQL，需自行 `fba --sql` 或重跑 init。

### 1.7 加载 `[settings]`

`backend/plugin/settings_source.py` 的 `PluginSettingsSource`：遍历含 `__init__.py` 的插件目录，读 `plugin.toml` 的 `[settings]` 并 merge。

过滤规则：

- 字段在 `Settings` 中**且 default 为 `PydanticUndefined`（必填无默认）**：采用插件值作 fallback。
- 字段在 `Settings` 中**且已有默认值**：插件值被丢弃。
- 字段不在 `Settings`：因 `extra='allow'` 会挂到 settings 上。

`Settings.settings_customise_sources` 顺序（`backend/core/conf.py`）：

```python
return env_settings, dotenv_settings, PluginSettingsSource(settings_cls)
```

即：**系统环境变量 > `.env` > 插件 `[settings]` > conf.py 默认值**。  
动态配置（config 插件）是运行时覆盖层，优先级最高，但不是 Pydantic source。

### 1.8 启用 / 禁用（Redis，不是数据库表）

**没有插件启用状态表。** 状态只在 Redis：

- Key：`{PLUGIN_REDIS_PREFIX}:{plugin}` → `fba:plugin:rider_salary`
- JSON 内 `plugin.enable`：`"1"` 启用 / `"0"` 禁用（`StatusType.enable/disable`）
- 变更标记：`fba:plugin:changed`

首次解析缓存缺失时，`get_plugin_enable(..., default=enable)` **默认启用**。

切换接口（超管）：

```python
# backend/app/admin/api/v1/sys/plugin.py
@router.put('/{plugin}/status', summary='更新插件状态', dependencies=[DependsSuperUser])
async def update_plugin_status(...):
    await plugin_service.update_status(plugin=plugin)
```

`PluginService.update_status` 翻转 `enable` 并写 Redis。

请求期校验 `PluginStatusChecker`（`backend/plugin/status.py`）：缓存缺失会尝试 `repair_plugin_cache`（修好后默认 enable）；若 `enable != "1"` 抛 `ServerError(msg=f'插件 {self.plugin} 未启用，请联系系统管理员')`。

结论：

- 路由：启动时对**全部**合法应用/扩展插件注入，禁用后接口仍在 OpenAPI 里，请求被 500 拦住。
- hooks：只跑**已启用**插件。
- 改状态后需注意：进程内路由已注入；`changed` 标记给前端提示重启。开发环境热重载会重新 `parse_plugin_config`。

### 1.9 hooks

框架加载器：`backend/plugin/hooks.py`（不是每个插件都有；内置插件目前都没有自己的 `hooks.py`）。

插件根目录可选 `hooks.py`，仅对已启用且可注入路由的插件加载：

| 函数 | 签名 | 时机 |
|------|------|------|
| `lifespan` | FastAPI lifespan 风格 | 注册到 `LifespanStage.plugin` |
| `setup` | `setup(app: FastAPI)` 可 sync/async | 启动前 |
| `otel` | `otel(app: FastAPI)` | OTel 初始化 |

替换中间件用 `backend/plugin/patching.py` 的 `replace_middleware(app, Original, Replacement, **kwargs)`，应在 `setup` 里调用。

## 2. 模型层

### 2.1 基类与主键（`backend/common/model.py`）

```python
id_key = Annotated[
    int,
    mapped_column(
        BigInteger, primary_key=True, unique=True, index=True,
        autoincrement=True, sort_order=-999, comment='主键 ID',
    )
    if PrimaryKeyType.autoincrement == settings.DATABASE_PK_MODE
    else mapped_column(
        BigInteger, primary_key=True, unique=True, index=True,
        default=snowflake.generate, sort_order=-999, comment='雪花算法主键 ID',
    ),
]
```

类层次：

| 类 | 含义 |
|----|------|
| `MappedBase` | `AsyncAttrs + DeclarativeBase`，自动 `__tablename__=类名.lower()`，`__table_args__={'comment': docstring}` |
| `DataClassBase` | `MappedAsDataclass + MappedBase`，`__abstract__=True` |
| `Base` | `DataClassBase + DateTimeMixin + LogicalDeleteMixin` |
| `DateTimeMixin` | `created_time` / `updated_time` |
| `LogicalDeleteMixin` | `deleted`（0 未删；删除时写自身 id）/ `deleted_time` |
| `UserMixin` | `created_by` / `updated_by`（**当前无业务模型使用**；数据权限 `__created_by__` 需要它） |

业务模型应：

```python
class RiderSalaryPayroll(Base):
    """薪资单"""
    __tablename__ = 'rider_salary_payroll'
    id: Mapped[id_key] = mapped_column(init=False)
```

日志类表可只用 `DataClassBase`（如 `OperaLog` 无逻辑删除）。

### 2.2 时间字段约定

`DateTimeMixin`：

```python
created_time: Mapped[datetime] = mapped_column(
    TimeZone, init=False, default_factory=timezone.now, sort_order=999, comment='创建时间',
)
updated_time: Mapped[datetime | None] = mapped_column(
    TimeZone, init=False, onupdate=timezone.now, sort_order=999, comment='更新时间',
)
```

- 列类型是本文件的 `TimeZone` TypeDecorator（不是 `utils.timezone.TimeZone`）。
- `created_time` 插入时由 `timezone.now` 填；`updated_time` 仅 `onupdate`，新建时可为 `None`。
- `init=False`：构造 dataclass 时不要传这两个字段。

### 2.3 时区（`backend/utils/timezone.py`）

```python
class TimeZone:
    def __init__(self) -> None:
        if settings.DATETIME_TIMEZONE in _UTC_IDENTIFIERS:
            self.tz_info = datetime_timezone.utc
        else:
            self.tz_info = zoneinfo.ZoneInfo(settings.DATETIME_TIMEZONE)
    def now(self) -> datetime: ...
    def from_datetime(self, t: datetime) -> datetime: ...
    def from_str(self, t_str: str, format_str: str = settings.DATETIME_FORMAT) -> datetime: ...
    def to_str(t: datetime, format_str: str = ...) -> str: ...
    def to_utc(t: datetime | int) -> datetime: ...

timezone: TimeZone = TimeZone()
```

默认 `DATETIME_TIMEZONE = 'Asia/Shanghai'`，`DATETIME_FORMAT = '%Y-%m-%d %H:%M:%S'`。  
模型侧 `TimeZone` TypeDecorator：写入时若 offset 与当前配置不一致则 `from_datetime`；读出若 naive 则补 `timezone.tz_info`。

Schema 的 `SchemaBase.json_encoders` 会把 datetime 格式化成该字符串。

### 2.4 跨库类型

已有：

```python
class UniversalText(TypeDecorator[str]):
    impl = LONGTEXT if DataBaseType.mysql == settings.DATABASE_TYPE else Text

class TimeZone(TypeDecorator[datetime]):
    impl = DateTime(timezone=True)
```

JSON：源码直接 `sa.JSON()`（`sys_opera_log.args`、Celery scheduler args）。PostgreSQL/MySQL 均可。不要用 PG 专有 `JSONB` 除非只支持 PG。

金额：代码生成模板把 `DECIMAL`/`NUMERIC`/`MONEY` 映射为 Python `Decimal` + `sa.Numeric()`。推荐：

```python
from decimal import Decimal
import sqlalchemy as sa

amount: Mapped[Decimal] = mapped_column(sa.Numeric(12, 2), comment='金额（元）')
```

`TypeDecorator` / `with_variant` 用于真正的方言差异。插件若声明 `database = ['mysql', 'postgresql']`，模型必须两边都能 create。

### 2.6 模型如何进入 metadata / Alembic

`backend/__init__.py` 启动即 `get_all_models()`：扫描 `backend.app.*.model` 与 `backend.plugin.*.model`，类注册进 `MappedBase.metadata`。

因此：

- `fba init` 的 `create_all`、lifespan 里 `create_tables()`、`fba add` 的 `create_all` 都会建插件表。
- `fba alembic revision --autogenerate` 的 `env.py` 虽然只 import `MappedBase`，但 `from backend.common.model` 会先执行 `backend/__init__.py`，插件模型会被看到。

**官方插件惯例：首次安装不写 Alembic 迁移，不在 init.sql 里 CREATE TABLE。**  
`code_generator` 的 `init.sql` 只 insert 菜单和种子行；`destroy.sql` 才 `DROP TABLE`。

开发期改表：改模型后开发库可重建（`fba init`）。上线后演进：用 `fba alembic revision --autogenerate -m "..."` + `fba alembic upgrade head`。init.sql 只服务全新安装。

当前仓库 `backend/alembic/versions` 目录甚至还不存在，说明基线靠 `create_all` + SQL 种子。

### 3.1 CRUDPlus 常用方法

包：`sqlalchemy-crud-plus==1.13.3`（`uv.lock`）。类：`CRUDPlus[Model]`。

源码签名（第三方库 `sqlalchemy_crud_plus/crud.py`）：

```python
async def select_model(self, session, pk, *whereclause, load_options=None, load_strategies=None, join_conditions=None, **kwargs) -> Model | None
async def select_model_by_column(self, session, *whereclause, ..., **kwargs) -> Model | None
async def select(self, *whereclause, ..., **kwargs) -> Select
async def select_order(self, sort_columns, sort_orders=None, *whereclause, ..., **kwargs) -> Select
async def select_models(self, session, *whereclause, ..., limit=None, offset=None, **kwargs) -> Sequence[Model]
async def select_models_order(self, session, sort_columns, sort_orders=None, *whereclause, ..., limit=None, offset=None, **kwargs) -> Sequence[Model]
async def create_model(self, session, obj, flush=False, commit=False, **kwargs) -> Model
async def create_models(self, session, objs, flush=False, commit=False, **kwargs) -> list[Model]
async def update_model(self, session, pk, obj, flush=False, commit=False, **kwargs) -> int
async def update_model_by_column(self, session, obj, allow_multiple=False, flush=False, commit=False, **kwargs) -> int
async def delete_model(self, session, pk, flush=False, commit=False) -> int
async def delete_model_by_column(self, session, allow_multiple=False, logical_deletion=False, deleted_flag_column='is_deleted', deleted_flag_value=True, deleted_at_column='deleted_at', deleted_at_factory=None, flush=False, commit=False, **kwargs) -> int
```

过滤 kwargs 用 `field__operator`：`username__like`、`id__in`、`phone__startswith`。  
**分页不要用 `select_models` + limit**；用 `select_order` 得到 `Select`，交给 Service 的 `paging_data`。

fba CRUD 封装约定（见 `notice`）：

```python
# backend/plugin/notice/crud/crud_notice.py
class CRUDNotice(CRUDPlus[Notice]):
    async def get(self, db, pk):
        return await self.select_model(db, pk, deleted=0)

    async def get_select(self, title, type, status) -> Select:
        filters = {'deleted': 0}
        ...
        return await self.select_order('created_time', 'desc', **filters)

    async def create(self, db, obj):
        await self.create_model(db, obj)

    async def delete(self, db, pks: list[int]) -> int:
        return await self.delete_model_by_column(
            db, allow_multiple=True, logical_deletion=True,
            deleted_flag_column='deleted', deleted_flag_value=self.model.id,
            deleted_at_column='deleted_time', deleted_at_factory=timezone.now(),
            id__in=pks, deleted=0,
        )
```

注意：逻辑删除标记列是 `deleted`，值是**行自己的 id**（不是 1）。查询一律 `deleted=0`。

`select_order` 只返回 SQL，**不执行**；`select_models_order` 会执行。部门树用后者并传入 `data_filter`：

```python
return await self.select_models_order(db, 'sort', 'asc', data_filter, **filters)
```

CRUD 层不要 `commit=True`；事务由 API 的 `CurrentSessionTransaction` 或 `async_db_session.begin()` 提交。

### 3.7 i18n：能否全中文硬编码？

机制：`backend/common/i18n.py` 的 `t(key, default=None, **kwargs)`，语言包 `backend/locale/zh-CN.yml`、`en-US.json`。中间件读 `Accept-Language`。

`t()` **不是强制**：ruff 无相关规则，插件代码大量中文 `msg=`。

会走 i18n 的路径：

- `response_base.success()` 默认 `CustomResponseCode.HTTP_200.msg` → `t('response.success')` →「请求成功」
- `CustomErrorCode.CAPTCHA_ERROR` → `t('error.captcha.error')`
- 登录成功日志 `t('success.login.success')`

绕过：`response_base.success(res=CustomResponse(code=200, msg='操作成功'))`；异常一律 `msg='中文'`。  
Pydantic 校验错误会按语言包翻译，与业务硬编码不冲突。

**结论：插件全中文硬编码可行，不必为业务文案加 locale。** 不要依赖改 `backend/locale`（那是框架文件）。

### 4.6 数据权限：能否「站点负责人只看本站点」？

可以，但是**配置型、按列等值/集合过滤**，不是自动树形「本部门及以下」。

链路：用户 → 角色 → `sys_role_data_scope` → `sys_data_scope` → `sys_data_scope_rule` → `sys_data_rule`。

规则字段（`DataRule`）：`model`（ORM 类名，如 `RiderSalaryPayroll` 或 `__ALL__`）、`column`、`operator`（0 AND / 1 OR）、`expression`（0== 1!= 2> 3>= 4< 5<= 6 in 7 not_in）、`value`。

模板变量：

- 列：`__dept_id__` → `dept_id`；`__created_by__` → `created_by`
- 值：`${user_id}` / `${dept_id}` / `${now}`

`filter_data_permission`：超管不过滤；角色 `is_filter_scopes=False` 不过滤；启用过滤但无规则 → **空结果**（`1 != 1`）。

用法：

```python
data_filter: Annotated[ColumnElement[bool], Depends(DataPermissionFilter(RiderSalaryPayroll))]
# CRUD: select_models_order(db, 'id', 'desc', data_filter, deleted=0)
```

种子示例（`init_test_data.sql`）：

```sql
insert into sys_data_rule (id, name, model, "column", operator, expression, "value", created_time, updated_time)
values
(1, '部门 ID 等于当前用户部门', 'Dept', '__dept_id__', 0, 0, '${dept_id}', now(), null),
(5, '全模型部门 ID 等于当前用户部门', '__ALL__', '__dept_id__', 0, 0, '${dept_id}', now(), null);
```

落地建议：

1. 若站点 = 部门：业务表加 `dept_id`，规则 `model=RiderSalaryPayroll, column=dept_id, expr==, value=${dept_id}`。站点负责人用户的 `sys_user.dept_id` 必须是该站点。**不含下级部门**，下级要用 `in_` + 逗号 id 列表，或在 Service 里自己算子树。
2. 若自建 `rider_salary_site`：业务表加 `site_id`。数据规则的列模板只有 `__dept_id__`/`__created_by__`，**没有 `${site_id}`**。可选：(a) 站点 id 与 dept_id 相同；(b) 用户 dept 映射站点，规则仍用 `dept_id`；(c) 插件 Service 里显式 `site_id == request.user.xxx`，不走框架数据权限。
3. 需要「创建人」过滤时给模型混入 `UserMixin`。

**推荐：自建站点表，并冗余 `dept_id`（或让 site.id 与 dept 对齐），列表接口挂 `DataPermissionFilter`。** 复杂范围在 Service 补过滤，不要改框架 permission.py。

`AuthService.login`：`load_login_config(db)` 后若 `settings.LOGIN_CAPTCHA_ENABLED`（默认 **True**），则 uuid/captcha 必填，Redis key `fba:login:captcha:{uuid}`。

关闭验证码（不改框架的路径）：

1. 管理端「参数配置」插件写入 `LOGIN_CAPTCHA_ENABLED=false`（`load_login_config` 映射了该键）并启用登录配置。
2. 开发期改 `backend/.env` 或环境变量 `LOGIN_CAPTCHA_ENABLED=false`（字段在 conf.py 有默认 True，**插件 [settings] 覆盖不了有默认的字段**；必须 env / 动态配置）。
3. 改 `conf.py` 默认值属于改框架，发布插件不能这么做。

测试 fixture 走 swagger 登录，避开验证码：`POST /auth/login/swagger`，用户 `admin` / `123456`。

### 5.4 部门 vs 站点

`sys_dept`（`backend/app/admin/model/dept.py`）：`name`、`sort`、`leader`、`phone`、`email`、`status`、`parent_id`。树形，无经纬度/线路/结算主体等物流字段。

**建议：自建 `rider_salary_site`，可选 `dept_id`。**

| 方案 | 优点 | 缺点 |
|------|------|------|
| 只用 dept | 数据权限 `${dept_id}` 开箱即用；用户已有 dept_id | 站点属性塞部门表会脏；改框架部门模型被禁止 |
| 自建站点表 + 可选 dept_id | 业务字段自由；仍能挂数据权限 | 多一张表、需同步负责人账号的 dept_id |
| 站点表不关联 dept | 最干净 | `${dept_id}` 不能直接过滤站点，要自己写过滤 |

推荐第二方案：站点负责人同时是该 `dept` 成员；薪资单存 `site_id` + `dept_id`（或仅 site_id，Service 用用户 dept 反查站点）。

## 6. 操作日志

### 6.1 记录字段

中间件：`backend/middleware/opera_log_middleware.py`。  
表：`sys_opera_log`。入参 schema：`CreateOperaLogParam`。

写入字段：`trace_id`、`username`（`request.user.username`，未登录 None）、`method`、`title`（见下）、`path`、`ip`、`country`、`region`、`city`、`user_agent`、`os`、`browser`、`device`、`args`（query/path/json/form，密码类 key 脱敏）、`status`（1 正常 0 异常）、`code`、`msg`、`cost_time`、`opera_time`。

条件：path 以 `/api/v1` 开头、不在 `OPERA_LOG_PATH_EXCLUDE`、非 OPTIONS。异步队列批量入库。

**summary / title 来源：** 请求结束后 `request.scope['route'].summary`，即路由装饰器的 `summary=`。不是业务「原因」。

`args` 来自请求参数，不是响应体。业务 JSON 里若有 `reason` 字段会出现在 `args.json.reason`，但这是请求快照，中间件无 API 可设「操作原因」。

### 6.2 能否携带业务「原因」？

不能干净地做到。把原因放进请求 body 只能出现在 `args` 里，和查询参数混在一起，且 GET 无 body。改中间件属于改框架。

### 6.3 结论：需要插件自建业务审计表

操作日志满足：谁（username）、何时（opera_time）、哪个接口（path/summary）、请求参数、成功失败。  
不满足：业务对象 id、动作枚举（核算/调薪/作废）、**为什么**、变更前后快照、与薪资单的外键。

**必须自建**例如 `rider_salary_audit_log`：`operator_id`、`operator_name`、`action`、`target_type`、`target_id`、`reason`、`before_json`、`after_json`、`created_time`。Service 在同一事务写入。操作日志仍作安全审计，两套并存。

## 8. 任务 / 异步

### 8.1 Celery（`backend/app/task`）

- 入口：`backend/app/task/celery.py`，实例 `celery_app`。
- Broker：dev 默认 Redis DB `CELERY_BROKER_REDIS_DATABASE`；prod 强制 RabbitMQ。
- Backend：业务数据库（`db+postgresql+psycopg` / `mysql+pymysql`）。
- 发现：`find_task_packages()` **只扫 `backend/app/task/tasks/**/tasks.py`**，**不会自动发现插件目录**。
- CLI：`fba celery worker|beat|flower`（worker 默认 gevent）。
- 基类 `TaskBase`：SQLAlchemyError 自动重试，`CELERY_TASK_MAX_RETRIES=5`。
- 示例：`@celery_app.task(name='task_demo')`。

大批量导入/重算（分钟级、要进度/重试/不阻塞 API）：适合 Celery。  
插件任务两种不改框架的办法：

1. `hooks.py` 的 `setup` 里 `celery_app.autodiscover_tasks(['backend.plugin.rider_salary.tasks'])`（需 worker 也能 import 插件包）。
2. 把任务文件放到 `backend/app/task/tasks/rider_salary/tasks.py`——这是改框架 app，发布型插件不推荐。

### 8.2 BackgroundTasks

登录成功写登录日志：

```python
background_tasks.add_task(login_log_service.create, user_uuid=..., username=..., ...)
```

跑在 **FastAPI 进程内、响应返回后**，无持久化、无重试、进程挂了就丢。适合发邮件验证码、轻量日志。

### 8.3 建议

| 场景 | 选择 |
|------|------|
| 登录日志、发验证码 | `BackgroundTasks` |
| Excel 导入数百行、当场校验 | 同步 Service + `CurrentSessionTransaction`（简单） |
| 导入数千行 / 全站重算 / 要进度条 | **Celery** + 结果表；API 只创建任务 |
| 定时「每月 1 号核算」 | Celery beat / 内置 scheduler（`fba celery beat`） |

不要用 BackgroundTasks 做薪资重算。Worker 必须单独进程；只起 `fba run` 不会消费队列。

## 11. 第三方库建议

原则：插件 `requirements.txt` 声明，少写解析器/日历/Excel 轮子。下列均不在当前 `uv.lock`，需插件自带。

### 11.1 安全表达式求值（计薪公式）

| 库 | 特点 | 适合公式？ |
|----|------|------------|
| **simpleeval** | 沙箱、白名单函数、无 import、轻 | **是，首选** |
| asteval | 更大 Python 子集，可对数/numpy，攻击面更大 | 备选 |
| rule-engine | 对象匹配规则（`user.age > 18`），不是算术引擎 | 否 |
| json-logic | JSON AST，前端可视化友好，四则运算啰嗦 | 规则配置 UI 时再考虑 |

推荐 **simpleeval**：计薪是 `base + overtime * rate - deduct`，需要沙箱。最小用例：

```python
from decimal import Decimal
from simpleeval import SimpleEval

s = SimpleEval()
s.functions = {'min': min, 'max': max, 'round': round}
s.names = {
    'attendance_days': Decimal('26'),
    'base': Decimal('8000'),
    'overtime_hours': Decimal('12'),
    'hour_rate': Decimal('40'),
}
s.operators[type(s.operators)]  # 保持默认算术
result = Decimal(str(s.eval('base + overtime_hours * hour_rate')))
```

禁止 `eval`/`exec`。把公式存在插件表，变量名白名单（出勤、里程等）。金额中间过程用 `Decimal`，simpleeval 对 Decimal 支持有限，求值后立刻 `Decimal(str(...))` 并 `quantize`。

### 11.2 Excel / CSV

| 库 | 角色 |
|----|------|
| **python-calamine** | 读 xlsx/xls 最快（Rust） |
| **openpyxl** | 写 xlsx、模板、表头样式 |
| pandas | DataFrame 清洗；体积大，非必须 |
| csv 标准库 | CSV 足够 |

推荐组合：**python-calamine（导入读）+ openpyxl（导出写）**。CSV 用标准库。不要为了读一张表引入 pandas。

### 11.3 中国法定节假日

PyPI 包名：**`chinese-calendar`**（import：`chinese_calendar`，不是 `chinesecalendar`）。

```python
import datetime as dt
from chinese_calendar import is_holiday, is_workday, get_holiday_detail

d = dt.date(2026, 10, 1)
is_holiday(d)          # True
is_workday(d)          # False
on_holiday, name = get_holiday_detail(d)  # (True, '国庆节')
```

注意每年需升级包以覆盖新放假安排。调休：`is_workday` 已处理「周末上班」。

### 11.4 金额 Decimal

- 模型：`Mapped[Decimal] = mapped_column(sa.Numeric(12, 2))`（或 14, 2）。
- Schema：`amount: Decimal = Field(description='金额（元）')`。
- 运算：`from decimal import Decimal, ROUND_HALF_UP`；禁止 float 累加。
- JSON：Pydantic 默认 Decimal 可序列化；msgspec 响应需确认（fba 默认 `MsgSpecJSONResponse`）。必要时 schema 用字符串分或 `PlainSerializer`。
- `backend/utils/serializers.py` 已有 Decimal 处理分支，join 序列化相对安全。

### 11.5 当前 uv.lock 可复用版本

| 包 | 锁定版本 |
|----|----------|
| fastapi-pagination | **0.15.16**（extra sqlalchemy） |
| msgspec | **0.21.1** |
| sqlalchemy-crud-plus | **1.13.3** |
| celery | **5.6.3** |
| pydantic | ≥2.13.4（以 lock 为准） |
| sqlalchemy | ≥2.0.52 |
| bcrypt / pwdlib | 密码 |
| rtoml | plugin.toml |
| fastapi-pagination 已集成 | 不要另引入一套分页 |

不要在插件里重复实现 CRUDPlus / 分页 / JWT。

## 12. 编码规范摘要

来源：`.agents/skills/fba/references/coding-style.md` + `pyproject.toml`。

### 12.1 引号

Ruff format：`quote-style = "single"`；lint `flake8-quotes.inline-quotes = "single"`。  
Python **单引号**。SQL / TOML / Markdown 按各语言习惯。

### 12.2 注释 / docstring

- 项目注释用**中文**，只在有信息增量时写。
- docstring：reStructuredText；有参数时用 `:param xxx:`；`:return:` 后不写描述；不要 `:raise:` / `:rtype:`。
- 不要 shebang、encoding 声明、文件头说明、`__all__`。
- `__init__.py` 默认空；`model/__init__.py` 必须导入全部模型类（官方要求）。

### 12.3 导入

- 每条 import 一个模块；禁止 `import *`；绝对导入。
- isort（ruff `I`）：`case-sensitive = true`，`lines-between-types = 1`，`order-by-type = true`。
- 第三方与本包之间空一行（stdlib / third party / `backend`）。
- 路由导入：`from ...xxx import router as xxx_router`。

### 12.4 其它

- 全 API/Service/CRUD 异步；Service 方法 `*` 仅关键字参数。
- 函数体内空行只分隔「逻辑阶段」，同阶段不要空行。
- 类型：`X | None`、`Annotated`。
- 行宽 120。`fba format` 或 `ruff format` + `ruff check --fix --unsafe-fixes`。

### 12.5 Ruff 配置位置

`fastapi-best-architecture/pyproject.toml`：

- `[tool.ruff]`：line-length=120，preview/fix/unsafe-fixes
- `[tool.ruff.lint]`：select 很长（含 `I` isort、`E`/`W`/`F`、`RUF` 等）
- `[tool.ruff.lint.flake8-quotes]`
- `[tool.ruff.lint.isort]`
- `[tool.ruff.format]` quote-style=single

插件代码同样被根配置扫到（包在 `backend/plugin`）。

## 13. 插件开发禁区

下列若「必须改 fba 框架源码」才能做，会破坏可插拔发布。尽量用右列替代。

| 诉求 | 改框架？ | 不改框架的路径 |
|------|----------|----------------|
| 增加 typed 配置项到 `conf.py` | 开发期允许、发布期禁止改用户文件 | `plugin.toml` `[settings]` + `.env.example`；README 说明；extra 字段仍能 `settings.XXX` |
| 覆盖已有默认配置（如关验证码） | 不要改 conf 默认 | 环境变量 / `.env` / config 插件动态配置 |
| 注册**新**中间件 | 不要改 `registrar.register_middleware` | `hooks.py` `setup(app)` → `app.add_middleware(...)` 或 `replace_middleware` |
| 改 JWT / 登录校验逻辑 | 是（`auth_service.py`、`jwt.py`） | 验证码用动态配置；登录后逻辑放插件接口；不要 fork 登录 |
| 改 RBAC 为 Casbin | 改 `RBAC_ROLE_MENU_MODE` + 装插件 | 保持角色-菜单；权限码写 init.sql |
| 全局白名单加路径 | 改 `TOKEN_REQUEST_PATH_EXCLUDE` | 插件接口用 `DependsJwtAuth`；公开接口尽量不需要白名单 |
| Celery 自动发现插件任务 | `celery.py` 的 `find_task_packages` 写死 app/task | `setup` 里 `autodiscover_tasks`；或 API 派发时显式 `celery_app.send_task` |
| 改操作日志增加 reason | 改中间件 | 自建业务审计表 |
| 给 `sys_user` 加骑手字段 | 改 admin 模型/迁移 | 插件扩展表 1:1 `user_id` |
| 改 `sys_dept` 当站点主数据 | 改部门模型 | 自建 `rider_salary_site` |
| 改 i18n 语言包 | 改 `backend/locale` | 业务 msg 硬编码中文 |
| 改分页默认 size | 改 `pagination.py` | 调用方传 `size` |
| 种子角色菜单 | 可改主 `init_test_data.sql`（框架 SQL） | 插件 SQL 只插菜单，或插件 SQL 自己 insert `sys_role_menu`（不改框架文件） |
| Alembic 环境 | 一般不用改 `env.py` | 模型被 `backend/__init__.py` 自动注册 |
| 必需插件列表 | `PLUGIN_REQUIRED` | 不要把自己做成必需插件 |
| 跨库不兼容类型 | — | `UniversalText` / `TimeZone` / `Numeric` / `JSON` |

**明确允许的插件内文件：** `api/` `crud/` `model/` `schema/` `service/` `sql/` `utils/` `hooks.py` `plugin.toml` `README.md` `requirements.txt` `.env.example` `enums.py`。

**不要做：** 修改 `fastapi-best-architecture/backend/core/conf.py` 作为发布步骤；修改 `registrar.py`、`jwt.py`、`auth_service.py`、`opera_log_middleware.py`、`celery.py` 的发现逻辑；在 init.sql 里 `ALTER TABLE sys_user`。

## 15. 风险点汇总

1. 插件禁用只存在 Redis，丢缓存会按默认启用修复；不要假设有 DB 状态表。
2. `create_all` 不改已有列；上线后改表必须 Alembic 或手工 SQL，只改 init.sql 救不了旧库。
3. 逻辑删除值是 id 不是 1；漏 `deleted=0` 会查到垃圾数据。
4. 数据权限无规则且 `is_filter_scopes=True` 时结果为空，易误判为 bug。
5. 非超管必须绑 `sys_role_menu`，否则按钮接口 403。
6. Celery 默认看不见插件任务。
7. `[settings]` 盖不住 conf.py 里已有默认值的项。
8. 雪花 id 前端精度；Detail schema 已有序列化，自定义响应别绕过 SchemaBase。
9. `UserMixin` 未使用则 `__created_by__` 规则无效。
10. 管理端安装插件不跑 SQL，开发应用 `fba add` 才会跑。
11. 验证码默认开启，E2E 用 swagger 登录或关 `LOGIN_CAPTCHA_ENABLED`。
12. OperaLog 不能当业务审计。
