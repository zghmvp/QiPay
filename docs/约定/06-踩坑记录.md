# 06 · 踩坑记录

> 每条：现象 → 根因 → 正确做法。新坑追加到末尾并编号；对应的历史处理见 `docs/任务/待修复清单.md`。

## 路由与菜单

**#1 新增前端页面访问 404，`routes/index.ts` 明明写了**
根因：FBA 前端 `accessMode: 'backend'`，路由从 `sys_menu` 动态生成，`routes/index.ts` 不参与。
做法：4 份 init SQL 加 `sys_menu`（`type=1`，隐藏页 `display=0`，`component` 与文件路径一致）+ `sys_role_menu` 绑定，写 `sql/patch/` 对现网执行，**重新登录**。见 `02` §1、`05` 场景 D。

**#2 `sys_role_menu` 插入报 `ix_sys_role_menu_id` 唯一冲突**
根因：现网库有 init.sql 之外的行（其他插件/手工授权占了你准备用的 id），或自增序列落后于手写 ID。
做法：插入前 `select max(id)`；显式指定空闲 id 或先 `setval('sys_role_menu_id_seq', max(id))`；patch 一律 `where not exists (role_id, menu_id)` 幂等。

**#3 `fba init` 执行插件 SQL 整单回滚**
根因：FBA 的 SQL 解析器不接受文件开头 `--` 注释。
做法：init SQL 文件**不写前导注释**；单独补跑用 `psql -f`。不要在共享库上跑 `fba init`（会 drop 全部 ORM 表）。

## 前端布局

**#4 列表页表格高度异常、随内容缩小**
根因：`Page auto-content-height` → VxeGrid `height:'auto'` 之间被带 padding 的中间 div 打断 flex 高度链；站点列表在 query 内 N+1 拉负责人导致 reflow。
做法：所有列表页外层用 `views/_shared/PageContainer.vue`（已含 `flex h-full min-h-0 flex-col` 与 `:deep` 高度传递），Grid 直接作为其子节点；列内异步数据用独立 Cell 组件懒加载（`ManagerCountCell`）。

**#5 StrReplace 编辑 `.vue` 后出现重复 `</script>` / 孤儿变量**
根因：以 `</script>` 为锚点插入代码时锚点不唯一或落在 script 中间。
做法：以函数/组件声明附近的唯一上下文为锚点；编辑后立即跑 `vue-tsc` 并肉眼检查 `<script>` 与 `<template>` 边界。

## 时间与时区

**#6 夜间加价条件在 13:00 命中、23:05 不命中**
根因：`送达时刻` 按 UTC 取时分。
做法：时段类字段求值前转 Asia/Shanghai（`engine/context.py`）；用例 `test_night_window_shanghai_2305_hits_1300_misses` 守住。

## 数据一致性

**#7 兼职切全职后仍按兼职算薪 / 历史看不到切换时间**
根因：用工类型历史只允许一条 `end_date=null`，新增新段被重叠校验拦住，只能先删旧段；`rs_rider.employ_type` 也不同步。
做法：`rider_service.create_employ_history` 自动把上一开放段收尾到 `start_date-1`（审计 + mark_stale），并在新段覆盖今天时同步 `rs_rider.employ_type`。前端档案页「用工类型」Tab 展示完整时间线。

**#8 draft 薪资单重算后预支抵扣丢失 / 重复扣**
根因：重算未先回滚上一次 `advance.remaining` 扣减。
做法：`calc_service` 重算前按旧 payroll 的 advance 明细 `restore`，再按 cap 重扣（ARCH-1 #19）。

**#9 站点级锁账改写了骑手级周期覆盖的订单/奖惩**
根因：站点级操作未排除被骑手级周期覆盖的骑手与日期。
做法：站点级算薪/锁账/反冲重开跳过重叠的骑手级周期（`period_service`）；周期规则见 `04` §3.4。

**#10 方案回退把周期置 `reopened` 后仍无法纠错**
根因：`is_locked` 标记未随 reopen 解除。
做法：reopen 时 `_set_locked_flags(locked=False)`；回退 `confirm_text` 仅在存在 `paid` 薪资单时强制。

**#11 方案绑定「看不到骑手当前在用什么」**
根因：绑定抽屉只列区间，不解析生效段。
做法：以 `resolve_effective_plans` 为唯一真源，档案页 `BindingPanel` 展示今日生效方案 + 前后三个月生效段预览；日历、H5、算薪均调同一函数，不要各自实现「某天用哪个版本」。

## 接口契约

**#12 rollback 后前端不知道跳到哪个版本**
做法：`POST /plan-versions/{id}/rollback` 返回新 draft 的 `GetPlanVersionDetail`（含 id）；前端据此跳转编辑器，不要靠 `copied_from_id` 回查。

**#13 导出文件名回退为默认名**
根因：CORS 未暴露 `Content-Disposition`。
做法：`backend/.env` `CORS_EXPOSE_HEADERS` 追加 `Content-Disposition`（保留 `X-Request-ID`）后重启；前端 `utils/download.ts` 仍保留 `{站点}_{周期}_xxx.xlsx` 兜底。

**#14 `GET /plan-versions/active` 曾弹 404 toast**
现状：后端 `get_active_dropdown` 返回 `[]` 不再 404；前端 `getActivePlanVersionsApi` 已去掉吞错 try/catch（空列表正常），绑定页对网络失败仍本地兜底 `[]` + 空态文案。

**#15 审计操作人显示「用户88888」**
根因：FBA 种子把 `admin.nickname` 写成占位；部分模块自定义 `description` 直接读 `nickname`。
做法：`utils/audit.resolve_operator_name` 优先真实昵称，匹配 `^用户\d+$` 占位时回退 `username`。预支/导入/导出/周期/回退等自定义 description 已统一走该函数（观察项 #17 已修）。

**#16 `GET /riders` 挂的是 `rs:rider:add`**
状态：已修。改为只读依赖 `DependsJwtAuth, DependsPagination, DependsRBAC`（与方案列表等只读分页一致）。

## 环境与流程

**#17 登录 429 / 验证码拿不到**
做法：`/auth/login` 限流约 5 次/分钟，`/auth/captcha` 约 5 次/30 秒；脚本里验证码从 Redis `fba:login:captcha:<uuid>` 读，或用 `POST /auth/login/swagger`（HTTP Basic）拿 token。

**#18 后台进程随命令结束被杀**
根因：macOS 无 `setsid`。
做法：一律用 `scripts/start_all.sh`（Python `Popen(start_new_session=True)` 守护），不要手写 `nohup &`。

**#19 多个子代理同时重启 8000 端口互相打断**
做法：后端重启由编排者串行执行；子代理只改代码并在回复中声明「需重启后端」。

**#20 子代理拿不到父会话的浏览器标签（MCP）**
做法：验收改用 Playwright 脚本（`scripts/t2_acceptance.mjs`、`scripts/ux_check.mjs`，swagger token 注入 localStorage），截图落 `docs/验收截图/`。

**#21 PostgreSQL 18 在 macOS 启动失败「postmaster 变成多线程」**
做法：`export LC_ALL=en_US.UTF-8 LANG=en_US.UTF-8` 后 `pg_ctl start`；`start_all.sh` 已内置。不用 `brew services`。

## 引擎与方案

**#22 案例里把 `volumeLadder556(...)` 当函数调用**
根因：预设 helper 里同名常量是对象不是函数。
做法：阶梯统一用 `volumeLadder(模式, 档位, 字段)` 生成；写完 `vue-tsc` 立刻检查。

**#23 「周期有效单量」与「方案期内单量」混用导致跨段方案阶梯落错档**
做法：周期级阶梯默认用 `周期有效单量`；方案换段期间只想按本方案段单量计时才用 `方案期内单量`。口径见纲要 §10 #26–#31。试算面板已展示两字段对照数字。

**#24 保底项算出的补差不对**
根因：`GUARANTEE_TOPUP` 引用 `本期已计金额`，但排在其他周期项之前，取到的是不完整的累计值。
做法：保底项 `sort_order` 必须是周期阶段最后一项。编辑器保存时弱提示并可「沉底后再保存」；项列表对未沉底保底项打「建议沉底」Tag。不强制拦截。
