# 02 · 管理端前端约定（`src/plugins/rider-salary`）

> 基于当前仓库真实代码提炼。示例取自 `views/site`，可直接照抄结构。Antdv Next 组件 API 查 `.agents/skills/antdv-next/SKILL.md`。

## 0. 边界

- 只能改 `fastapi-best-architecture-ui/apps/web-antdv-next/src/plugins/rider-salary/**`。
- 不改 `package.json`；需要新 npm 依赖 → 在回复中申请，不擅自安装。
- 不用 `$t()`、不建 `langs/`，界面文字直接写中文字面量。

## 1. 路由真相：页面由数据库 `sys_menu` 决定（最容易踩的坑）

FBA 前端为 `accessMode: 'backend'`：登录后调 `GET /api/v1/sys/menus/sidebar` 拿菜单树，按每行 `component` 字段（如 `/plugins/rider-salary/views/rider/detail`）在 `pageMap`（`views/**/*.vue` + `plugins/**/*.vue` 的 glob）里找到组件并**动态注册 vue-router 路由**。因此：

- 插件 `routes/index.ts` **不是**运行时路由表；它只是路由清单的文档化副本（混合模式才生效）。改它不会让页面出现。
- 新页面（包括不在侧栏显示的详情页/编辑器页）必须在后端 `sql/*/init*.sql` 增加 `sys_menu` 行：`type=1`，`component` 与文件路径一致（不带 `.vue`），隐藏页 `display=0`，并给角色 `92001/92002/92003` 加 `sys_role_menu`。同时写 `sql/patch/NNN_*.sql` 对现网库执行。否则访问就是 404。
- 加了菜单行要**重新登录**（菜单在登录时拉取并缓存）。超管 `is_superuser=true` 看全部菜单，但仍需 `sys_menu` 行存在。
- 动态段路由写 `path='/rider-salary/rider/:id'`，前端 `route.params.id`。
- `routes/index.ts` 仍要同步维护（名称、path、component、`hideInMenu`），保证与 `sys_menu` 一一对应，便于追溯。

现有页面 ↔ component 对照以 `backend/plugin/rider_salary/sql/postgresql/init.sql` 为准（产品菜单页均已实现，不再使用 ComingSoon 占位）。

## 3. API 层（`api/site.ts`）

```ts
import type { PageResult } from '../types/common';
import type { SiteForm, SiteQuery, SiteResult } from '../types/site';
import { requestClient } from '#/api/request';

const BASE = '/api/v1/rider-salary/sites';

export async function getSiteListApi(params: SiteQuery) {
  return requestClient.get<PageResult<SiteResult>>(BASE, { params });
}
export async function getAllSitesApi() {
  return requestClient.get<SiteResult[]>(`${BASE}/all`);
}
export async function createSiteApi(data: SiteForm) {
  return requestClient.post(BASE, data);
}
export async function updateSiteApi(pk: number, data: Partial<SiteForm>) {
  return requestClient.put(`${BASE}/${pk}`, data);
}
```

- 命名：`get<Xxx>ListApi`（分页）、`getAll<Xxx>sApi`（下拉全量）、`get<Xxx>Api`（详情）、`create/update/delete<Xxx>Api`、动作 `<verb><Xxx>Api`（`lockPeriodApi`、`activatePlanVersionApi`）。
- `requestClient` 已解包 `{code,msg,data}` 并统一弹错误 toast；**不要在页面再 `message.error(e.msg)`**。需要静默的「可能为空」GET（如 `getActivePlanVersionsApi`）在 api 函数内 try/catch 返回 `[]`/`null`，页面按空态处理。
- 下载走 `utils/download.ts`（`requestClient.download` + `responseReturn: 'raw'`，文件名取 `Content-Disposition`；取不到时调用方传入中文兜底名，如 `周期薪资-${pk}.xlsx`、`预支明细.xlsx`）。

## 4. 类型层（`types/site.ts`）

- `XxxResult`：对应后端 `GetXxxDetail`（含 `id`、`*_label`、`created_time`）。
- `XxxForm`：对应 `CreateXxxParam`（更新用 `Partial<XxxForm>`）。
- `XxxQuery extends PageParams`：列表查询参数。
- 动作参数单独命名（`RiderLeaveParam`、`BindingForm`）。
- 字段名与后端 snake_case **保持一致**，不做 camelCase 转换。
- 金额字段类型用 `MoneyValue`（后端 Decimal 序列化为字符串）。

## 5. 枚举（`constants/enums.ts`）

```ts
export const ENABLE_STATUS_OPTIONS = opts([
  ['enable', '启用', 'success'],
  ['disable', '停用', 'default'],
]);
enumLabel(ENABLE_STATUS_OPTIONS, row.status)   // '启用'；空值返回 '—'
enumColor(ENABLE_STATUS_OPTIONS, row.status)   // 'success'
enumTagOptions(ENABLE_STATUS_OPTIONS)          // 给 Select / CellTag 用
```

- 与后端 `enums.py` **一一对应**，value 用英文原值；后端加枚举成员，这里必加。
- 颜色语义：`default` 草稿/停用/未开始，`processing` 进行中，`success` 完成/启用/发布，`warning` 待处理/下线，`error` 失败/驳回/作废。周期状态 open 蓝 / locked 橙 / paid 绿 / reopened 紫。新增枚举时先看同类枚举已用的颜色保持一致。
- 展示优先用后端返回的 `*_label`，前端 `enumLabel` 作兜底。

## 6. 页面骨架（列表页 `views/site/index.vue`）

```vue
<script lang="ts" setup>
const formOptions: VbenFormProps = { collapsed: true, schema: querySchema, showCollapseButton: true, submitButtonOptions: { content: '查询' } };
const gridOptions: VxeTableGridOptions<SiteResult> = {
  columns: useColumns(onActionClick),
  height: 'auto',
  proxyConfig: { ajax: { query: async ({ page }, formValues) =>
    getSiteListApi({ page: page.currentPage, size: page.pageSize, ...formValues }) } },
  rowConfig: { keyField: 'id' },
  toolbarConfig: { custom: true, refresh: true, refreshOptions: { code: 'query' } },
};
const [Grid, gridApi] = useVbenVxeGrid({ formOptions, gridOptions });
const [Drawer, drawerApi] = useVbenDrawer({ class: 'w-[480px]', destroyOnClose: true, async onConfirm() { /* validate → api → message.success → close → gridApi.query() */ } });
</script>

<template>
  <PageContainer>
    <Grid>
      <template #toolbar-tools>
        <VbenButton v-access:code="'rs:site:add'" @click="onCreate">新增</VbenButton>
      </template>
    </Grid>
    <Drawer :title="drawerTitle"><Form /></Drawer>
  </PageContainer>
</template>
```

- **外层必须是 `PageContainer`**（`Page auto-content-height` + flex 高度链），Grid `height: 'auto'`。不要在 Grid 外再包带 padding 的 div，会打断高度链导致表格自动缩小（踩坑 #4）。
- 非表格页（日历、工作台、档案）用 `PageContainer` 内自定义 flex 布局，滚动容器加 `min-h-0 flex-1 overflow-auto`。
- 顶部站点范围：涉及站点的页面放 `SiteSelect`，非管理员只看到可见站点（后端已过滤）。

### 6.1 `data.ts`

- `querySchema: VbenFormSchema[]` 查询表单；`xxxFormSchema` 新增/编辑表单；`useColumns(onActionClick)` 返回列定义。
- 表单校验 `rules: 'required' | 'selectRequired'`；联动用 `dependencies: { show, required, triggerFields }`。
- 枚举列 `cellRender: { name: 'CellTag', options: enumTagOptions(...) }`；操作列 `cellRender: { name: 'CellOperation', options: [...] }`，`options` 用 `hasAccessByCodes(['rs:x:y'])` 过滤按钮。
- 金额列用 `slots` 渲染 `MoneyText`。
- 操作列 `fixed: 'right'`，宽度按按钮数给足（3 个约 160，4 个约 210）。

### 6.2 抽屉/弹窗组件

- 页面内简单表单：`useVbenDrawer` + `useVbenForm` 直接在 `index.vue`（如站点）。
- 复杂/可复用：独立组件 `components/XxxDrawer.vue`，内部 `const [Drawer, drawerApi] = useVbenDrawer({ onOpenChange(open) { if (open) { const data = drawerApi.getData<T>(); ... } } })`；父组件 `useVbenDrawer({ connectedComponent: XxxDrawer })` 后 `drawerApi.setData(payload).open()`。回调通过 `setData({ onSuccess })` 传入。
- 可嵌入页面又可放抽屉的内容做成 `XxxPanel.vue`（props + emits + `defineExpose({ reload })`），抽屉只做薄封装（如 `BindingPanel` / `BindingDrawer`）。
- 危险操作先 `confirm({ content, icon: 'warning' })`；提交期间 `drawerApi.lock()`，finally `unlock()`。
- 成功提示 `message.success('操作成功')` 或更具体的中文。

### 6.3 需要「操作原因」的动作

```ts
const { ReasonModal, prompt } = useReasonModal();
const { reason } = await prompt({ title: '锁账原因' });   // reasonRequired 默认 true
await lockPeriodApi(row.id, reason);
```

- `ReasonPromptOptions`：`title` / `reasonRequired` / `extraHint` / `password` / `passwordRequired`（超管回退等需二次密码时用）；返回 `ReasonResult { reason, password? }`；用户取消则 reject。
- 模板里放一次 `<ReasonModal />`。后端 `REASON_REQUIRED_ACTIONS` 里的动作前端必须走这个流程，未填不发请求。

## 7. 权限

- 按钮 `v-access:code="'rs:site:add'"`；脚本内 `useAccess().hasAccessByCodes([...])`。
- 权限码与后端 `RequestPermission` / `init.sql` `perms` 完全一致；新动作先在后端 SQL 加按钮再用。
- 只读角色（负责人看科目/方案）没有按钮权限，页面要能在无按钮状态下正常展示。

## 8. 深链与页面间跳转（保持这些参数名）

| 参数 | 含义 | 当前消费页 |
|---|---|---|
| `site_id` | 站点 | 日历、工作台 |
| `rider_id` | 骑手 | 日历；骑手列表（收到后重定向到档案页） |
| `month` | `YYYY-MM` | 日历、工作台 |
| `date` | `YYYY-MM-DD` | 日历打开当日抽屉 |
| `id` | 记录 ID | 周期页自动打开详情抽屉 |
| `status` | 枚举值 | 订单 / 预支 / 周期列表预筛 |
| `stale` | `true` | 周期页预筛待重算 |
| `tab` | 档案页标签 `overview/binding/employ` | `rider/detail.vue` |
| `edit_id` | 打开编辑抽屉 | 骑手列表 |

- 新页面要消费 query 时**复用上表参数名**，并把新增的消费页补进表格。
- 跳转用 `router.push({ path, query })`，不拼字符串。
- 动态段路由：档案页 `/rider-salary/rider/:id`（`route.params.id`）；方案编辑器 `/rider-salary/plan/editor/:versionId`（`route.params.versionId`）。
- 日历「去绑定」→ 档案页 `tab=binding`；档案页「打开完整薪资日历」→ 日历页带 `month/rider_id/site_id`。

## 9. 共享组件用法速查

| 组件 | 用途 | 关键 props/行为（以组件源码 `defineProps` 为准） |
|---|---|---|
| `SiteSelect` | 可见站点下拉 | `v-model:value`，内部拉 `getAllSitesApi`，非管理员只见可见站点 |
| `RiderSelect` | 按站点级联搜索骑手 | `site-id`，远程搜索工号/姓名 |
| `SubjectSelect` | 科目下拉 | 可按 `direction` / `status` 过滤 |
| `StatusTag` | 枚举 → Tag | `:options` + `:value`，颜色取 enums |
| `MoneyText` | 金额 | `value`，负红正默认；`signed` 显示正负号 |
| `SalaryCalendar` | 纯展示月历（方案色带 + 日格） | props `month` / `days` / `planBands` / `selectedDate`，emit `select(date, inMonth)`；数据由父组件调 `calendar` API 后传入；档案页与日历页共用 |
| `ReasonModal` | 原因弹窗 | 通过 `useReasonModal().prompt()` |
| `PageContainer` | 页面外层 | 见 §6 |

新增跨页面组件放 `components/`，模块私有放 `views/<module>/components/`。

## 10. 方案编辑器特有约定

- 公式/条件 JSON 结构以后端 `engine/compiler.py` 为准；前端 `views/plan/helpers.ts` 负责 `defaultFormula / formulaKindOf / summarizeFormula / FIELD_GROUPS`，改引擎必同步。
- 字段、函数、运算符列表从 `GET /engine/fields|functions|operators` 拉，不硬编码。
- 案例库 `constants/plan-presets.ts`：项用 `subject_code` 引用科目，应用时 `buildItemsFromPreset(preset, subjects)` 解析为 id；缺科目抛 `缺少科目：CODE`。新增案例同步更新 `docs/设计/04-薪资方案案例库.md`。
- 只有未使用过的 `draft` 可编辑；其他版本进入编辑器为只读并提示「已使用或非草稿版本只读，请停用后复制为新版本再改」（后端 `assert_version_editable` 对应报错「仅草稿版本可以编辑」）。
- 启用前必须试算通过且内容未变（后端 `activate` 校验 `trial_passed` / `trial_hash`）；编辑器保存项后要引导用户重新试算。
