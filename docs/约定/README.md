## 与其他文档的关系

- `docs/设计/00-架构决策纲要.md`：字段级规格与业务决策的**唯一规格源**；本目录不重复其内容，只写「怎么按规范落地」。
- `docs/设计/03-后端骨架说明.md`：工具函数签名、路由前缀表、菜单/权限/角色表、第三方库；本目录 01 引用它。
- `docs/设计/02-开发子角色通用守则.md`、`docs/任务/前端-F0-通用约定.md`：初期给子代理的任务书，内容已并入本目录 01/02，保留供追溯。
- `.agents/skills/fba/`：FBA 框架通用规范；本目录写的是**本项目在 FBA 之上的具体约定**，冲突时以本目录为准（因为本目录基于实际代码）。

## 维护规则

- 代码约定变了，同一次改动内更新本目录对应文档；不要让文档滞后于代码。
- 新踩的坑写进 06；已修的问题在 `docs/任务/待修复清单.md` 标状态，并在 06 提炼为「正确做法」。
- 文档内引用代码用相对路径 + 符号名，不贴大段代码；示例片段保持与仓库一致，改代码时同步。
