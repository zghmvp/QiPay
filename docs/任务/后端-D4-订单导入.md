## 接口（前缀 `/api/v1/rider-salary`，权限 `rs:order:*`，站点范围过滤）
- GET `/orders` 分页：筛选 site_id/rider_id/日期范围/status/order_no/import_batch_id/is_locked；返回含骑手工号姓名、站点名、状态中文。
- GET `/orders/{id}`；POST `/orders` 单条补录（source=manual）；PUT `/orders/{id}` 纠错（reason 必填；before/after 审计）；DELETE `/orders/{id}`（reason 必填）。
- GET `/orders/import-template` → xlsx 模板（中文表头：站点编码*、骑手工号*、订单号*、配送距离(公里)*、商品重量(斤)*、下单时间*、送达时间、订单状态*、订单金额、备注；第二行示例数据；第三个 sheet「填写说明」列出状态枚举中文值、时间格式 `YYYY-MM-DD HH:mm:ss`）。
- POST `/orders/import`（multipart：file，form 字段 `site_id?`（若给定，文件内站点编码必须一致）、`skip_errors: bool=false`、`auto_recalc: bool=false`）：
  1. 大小/行数上限（`settings.RIDER_SALARY_IMPORT_MAX_ROWS`）；表头校验（缺列 → 「模板表头不符，缺少列：xxx」）。
  2. 逐行校验：站点存在且可见；骑手存在、在职（biz_date 在 hire_date~leave_date 内）、属该站点；订单号在文件内与库内唯一（库内重复 → 「订单号已存在」）；距离/重量 ≥0 数值；时间格式；送达 ≥ 下单；状态中文映射到枚举；biz_date 规则（送达日期，否则下单日期）；所属周期未锁账（`assert_not_locked`）。
  3. `skip_errors=false`：任一行失败 → 整批不入库，status=失败，返回错误报告；`true`：合法行入库，status=部分失败。
  4. 成功：创建 `rs_import_batch`（date_from/date_to 取入库行 biz_date 极值，error_report 存 `[{row, order_no, reason}]`），`mark_stale`（涉及骑手与日期范围），`auto_recalc=true` 时用 FastAPI `BackgroundTasks` 调 D3 的 `calc_service.calculate_period` 对涉及的 open 周期重算（若 D3 尚未提供，留 TODO 并在回复注明）。
  5. 返回 `{batch_id, total_rows, success_rows, failed_rows, status, errors:[前 100 条]}`。
- GET `/import-batches` 分页；GET `/import-batches/{id}`；GET `/import-batches/{id}/error-report` → xlsx 下载（行号、订单号、原因）。
- 状态中文↔枚举映射：已完成/已取消/配送异常/已退款；兼容常见别名（完成、取消、异常、退款）。

## 实现要求
- 解析用 `python-calamine`（xlsx/xls）与标准库 csv（自动探测 utf-8/utf-8-sig/gbk）；写用 `openpyxl`。
- 时间解析：接受 `YYYY-MM-DD HH:mm:ss`、`YYYY/M/D H:mm`、Excel 日期序列（calamine 返回 datetime）；统一为 FBA 时区 aware datetime。
- 所有写操作：审计 + 锁账校验 + mark_stale。
- 补录/纠错若改变 rider_id 或 biz_date，两侧 (rider, date) 都要 mark_stale。
