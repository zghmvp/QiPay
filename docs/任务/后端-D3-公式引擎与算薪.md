## 1. 引擎元数据（`/engine`，GET，需登录）
- `GET /engine/fields` → `[{name:'配送距离', type:'number'|'time'|'enum'|'bool'|'date', stages:['per_order'], unit:'公里', description, enum_options?:[{value,label}]}]`，完整实现纲要 §2.1 字段注册表（含按日/周期聚合字段）。
- `GET /engine/operators` → 按字段类型给可用运算符：number: `= ≠ > ≥ < ≤ 在区间内 不在区间内`；time: `在时段内 不在时段内 > <`；enum: `= ≠ 属于 不属于`；bool: `=`；date: `= > < 在区间内`。
- `GET /engine/functions` → `最大值 最小值 取整 向上取整 四舍五入 绝对值` 的签名与说明。
- `GET /engine/formula-templates` → 四种公式模板的 JSON 骨架与说明（固定金额/字段乘单价/阶梯/表达式）+ 快捷模板「底薪分摊」= 表达式 `底薪金额 × 方案生效天数 / 周期天数`（前端替换底薪金额常量）。
- `POST /engine/validate` body `{stage, condition_json, formula_json}` → `{ok, condition_expr, formula_expr, errors:[中文]}`：校验字段在该阶段可用、运算符与类型匹配、阶梯档位连续不重叠且升序、表达式只含白名单标识符与函数、除以常数 0。
- `POST /engine/evaluate-sample` body `{stage, condition_json, formula_json, context:{...}}` → 用给定上下文求值，返回 `{hit, amount, trace}`（前端编辑器即时预览）。

## 2. 编译与求值
- `compiler.compile_condition(json) -> str`：生成中文变量的 Python 表达式，如 `(在时段内(送达时刻, "22:00", "06:00")) and (配送距离 > 5) and ((是否节假日 == True) or (是否恶劣天气 == True))`；`且/或/非` → `and/or/not`；空条件 → `True`。
- `compiler.compile_formula(json) -> str`：固定金额 → `2`；字段乘单价 → `最大值(0, (配送距离 - 5)) * 0.8`；阶梯 → `阶梯(周期单量, "全量落档", "按单价", [[0,300,5],[300,600,5.5],[600,null,6]])`（阶梯作为白名单函数由 `ladder.py` 实现）；表达式 → 原样（经白名单校验）。
- `evaluator.evaluate(expr: str, names: dict) -> Any`：基于 `simpleeval.EvalWithCompoundTypes`（或 SimpleEval），`functions` 只注入白名单中文函数，`names` 为上下文；禁用属性访问；数值统一 float 求值，金额结果 `money.q2(Decimal(str(x)))`；时刻类型用「自 0 点起分钟数」表示，`在时段内(t, "22:00", "06:00")` 支持跨午夜。
- `ladder.ladder(value, mode, pricing, tiers)`：全量落档/分段累进 × 按单价/固定金额 四种组合；上限 null 表示无穷；下限含、上限不含。
- `context.py`：`build_order_context(order, day_ctx, rider_ctx)`、`build_day_context(site_id, biz_date, day_flag, employ_type)`（含 `是否节假日` 用 `chinese_calendar.is_holiday`、`是否周末`、`星期`）、`build_period_context(...)`、`build_segment_context(...)`，键名与 `fields.py` 完全一致。

## 3. 方案与版本（`/plans`、`/plan-versions`）
- `/plans`：CRUD（删除要求无版本或全部版本为 draft 且未使用）。
- `/plan-versions`：GET 分页（筛选 plan_id/status）；POST 创建 draft（version_no 自增）；GET `/{id}`（含 items 与 plan 信息、is_used、trial 状态、items_hash）；PUT `/{id}` 基本信息；DELETE `/{id}`（仅 draft 且未使用）；PUT `/{id}/items` 全量覆盖 items（逐项 validate，保存 condition_expr/formula_expr，重算 `items_hash` = sha256(规范化 JSON)，若 hash 变化则 `trial_passed=False`）。
- **不可变约束**：`is_used=True` 或 status≠draft 时，PUT/DELETE 版本与 items 一律 403「该方案版本已被使用，禁止编辑或删除，请停用后复制为新版本」。
- `POST /{id}/trial` body `{rider_id, start_date, end_date}`：以该版本为区间内唯一生效方案，调用 `calc_service.calculate(..., persist=False, forced_plan_version=version)`；订单数超过 `RIDER_SALARY_TRIAL_MAX_ORDERS` → 拒绝；返回 `{summary:{order_count, gross, deduction_total, net, per_order_total, daily_total, period_total, manual_bonus, manual_penalty}, per_order:[...含 calc_trace], daily:[...], period_items:[...], warnings:[...]}`；成功后写 `trial_hash=items_hash, trial_passed=True, trial_snapshot=summary`。
- `POST /{id}/activate`：要求 items ≥1、`trial_passed && trial_hash == items_hash`，否则「方案内容已变更，请重新试算」；status→active；审计。
- `POST /{id}/disable`（reason 必填）；`POST /{id}/copy` → 新 draft（复制 items，copied_from_id，version_no+1）。
- `GET /plan-versions/active` 下拉：`[{id, plan_name, short_name, color, version_no}]`。

## 4. 算薪流水线（`service/calc_service.py`）
按纲要 §3 伪代码逐行实现，签名：
```python
async def calculate_rider_period(db, *, rider_id: int, period: SettlePeriod, persist: bool = True, forced_plan_version: PlanVersion | None = None, operator=None) -> CalcResult
async def calculate_period(db, *, period_id: int, rider_ids: list[int] | None = None, operator=None) -> list[CalcResult]
```
- persist=True：找/建该 (period, rider) 的 draft payroll（period.status=reopened 时 kind=supplement，否则 normal）；status≠draft → 拒绝「已定稿结果不可重算，请走反冲补发」；删旧明细、写新明细、刷新 `rs_payroll_daily`、回填 `rs_adjustment.period_id`、预支抵扣（调用 `payroll_service.apply_advance_deduction`：按 paid 且 remaining>0 的 `rs_advance`，按 paid_time 先后，写 source=advance 的负明细并更新 advance 的 deducted/remaining/deduct_status —— 若 D6 尚未提供 advance 服务，你在 `payroll_service` 内直接操作 `rs_advance` 模型）、`calc_version+1`、`stale=False`、审计「重算」。
- persist=False（试算/预估）：不写任何表、不抵扣预支（但返回「可抵扣预支金额」参考值）。
- 段解析：`engine/segments.py::resolve_segments(db, rider_id, start, end, forced=None) -> list[Segment]`（forced 时整个区间一个段）。
- 无方案日：有有效订单但无段覆盖 → `rs_payroll_daily.day_status='no_plan'`，payroll.warnings 追加「YYYY-MM-DD 无生效方案，N 单未计薪」。
- 日状态：`has_data` / `no_orders`（该日站点有导入覆盖但骑手 0 单；覆盖判断 = 存在 rs_import_batch 覆盖该日 或 该站点该日存在任何订单）/ `not_imported` / `no_plan`。
- 反冲：`payroll_service.create_reversal(db, payroll, operator, reason) -> Payroll`：kind=reversal、status=finalized、明细取负、reversed_of_id、原单 reversed=True；`rs_payroll_daily` 不变。
- 所有金额 Decimal，逐项 `q2` 后汇总。
