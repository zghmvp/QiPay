## 1. 薪资日历（管理端，`rs:calendar:view`）
- GET `/calendar/{rider_id}?month=YYYY-MM` → 严格按纲要 §6 的 JSON 结构：`summary`（本月累计单量、应发、奖、惩、代扣、预支抵扣、实发、涉及周期及状态）、`days[]`（每日：order_count、valid_order_count、net_adjust、subjects 摘要（去重科目名 ≤3 个 + 「等N项」）、plan_version_id/short_name/color、day_status、period_id、period_status、is_locked）、`plan_bands[]`（由 `resolve_effective_plans` 得到的连续区间，月边界裁剪）。
  - 数据源：`rs_payroll_daily` 优先；若某日无缓存行，则实时从 `rs_order` 聚合单量、从 `rs_adjustment` 聚合净额，并按导入覆盖判断 `not_imported`/`no_orders`。
  - `summary` 金额来自该月涉及周期的最新有效 payroll（排除 voided/reversal；有 supplement 用 supplement）。
- GET `/calendar/{rider_id}/days/{date}` → `{date, plan:{version_id, plan_name, short_name, version_no, mode_tag}, period:{id, range, status}, day_flag, orders:[订单字段 + 该订单命中的明细 [{subject, amount, calc_trace}]], daily_items:[按日项明细], adjustments:[手工奖惩], totals:{order_count, formula_amount, manual_bonus, manual_penalty, net}}`。
- `calendar_service.build_month(db, rider_id, month)` 与 `build_day(db, rider_id, date)` 要被 `/me` 复用（同一函数，`/me` 侧只是 rider 来源不同）。

## 2. 工作台（`rs:dashboard:view`）
GET `/dashboard/summary?site_id?&month=YYYY-MM`（site_id 空=全部可见站点）返回：
- `cards`：在职骑手数、本月单量、本月有效单量、预计应发合计（最新 draft/finalized/paid payroll 汇总）、待审核预支数、待发放预支数。
- `attention`（每项含 `count`、`items`（≤10 条）与 `link`（前端路由 + query，如 `/rider-salary/period?status=open&stale=1`））：需重算周期（stale payroll 所在周期）、无方案日（rs_payroll_daily.day_status=no_plan，按骑手聚合）、待审核预支、导入覆盖缺口（本月 1 日至昨日，站点无任何批次覆盖且无订单的日期）、异常订单（status ∈ abnormal/refunded 或 配送时长>60 分钟 的本月订单）、即将到期周期（end_date 距今 ≤3 天且 open）、离职但仍有本月订单的骑手。
- `trend`：近 30 天每日单量与逐单金额 `[{date, order_count, formula_amount}]`。
- `top_riders`：本月单量 Top 10 与 单量最低 5 名（在职、有绑定）。
只返回有数据意义的模块：空数据返回空数组，前端自行隐藏。

## 3. 预支（管理端 `/advances`，权限 `rs:advance:*`；负责人仅本站点）
- GET 分页（筛选 site_id/rider_id/status/日期范围）；GET `/{id}`（含操作时间线）。
- POST `/{id}/approve` body `{remark?}`：pending → to_pay；审核人 = 当前用户；校验审核人对该站点可见。
- POST `/{id}/reject` body `{reason}`（必填）：pending → rejected。
- POST `/{id}/mark-paid` body `{remark?}`：to_pay → paid；`paid_time`、`remaining_amount=amount`、deduct_status=未抵扣。
- POST `/{id}/cancel` body `{reason}`（必填）：to_pay → cancelled（管理员取消）。
- GET `/advances/export?site_id&status&date_from&date_to` → xlsx（工号、姓名、站点、金额、原因、状态、申请时间、审核人、审核时间、发放时间、已抵扣、待抵扣）。
- 所有迁移集中于 `advance_service.transition(advance, target, operator, reason)`，非法迁移 → 400「预支单当前状态为 X，不允许执行 Y」。审计齐全。

## 4. 骑手端 `/me`（**仅 `DependsJwtAuth` + `DependsCurrentRider`，不加 DependsRBAC**）
- GET `/me/profile` → 工号、姓名、站点名、用工类型、入职日期、当前生效方案（short_name、plan_name、version_no、mode_tag、生效起止）、预支上限、当前是否有进行中预支。
- GET `/me/calendar?month` → 复用 `calendar_service.build_month`，但**裁掉** calc_trace 等内部字段仅保留骑手可见信息；`GET /me/days/{date}` 同理（订单列表 + 每单金额 + 科目名，不返回表达式）。
- GET `/me/payroll-estimate` → 当前周期（`get_or_create_period`）：若存在非 stale 的 draft/finalized/paid payroll → 返回其汇总；否则调用 `calculate_rider_period(persist=False)` 实时预估；返回 `{period_range, period_status, order_count, gross, deduction_total, advance_deduction_estimate, net_estimate, is_estimate: bool, updated_at}`。
- GET `/me/adjustments?month` → 本人奖惩列表（科目名、方向、金额、日期、备注）。
- GET `/me/plan` → 当前与未来已绑定方案（不含公式细节，只给项名称与科目）。
- GET `/me/notices` → 本站点 + 全站已发布公告，倒序。
- GET `/me/advance-limit` → `{limit, used_pending_amount, available}`。
- GET `/me/advances` 列表；POST `/me/advances` body `{amount, reason}`：校验在职、无 pending/to_pay 在途单（「您已有一笔预支申请在处理中，请等待处理完成后再申请」）、amount ≤ 上限（「预支金额超过上限 X 元」）、amount>0；创建即 pending（草稿态仅在前端存在，后端直接提交；若需草稿可 `POST /me/advances/draft`，本期不做）；审计（操作人=骑手）。
- POST `/me/advances/{id}/cancel`：pending → cancelled（本人）。
