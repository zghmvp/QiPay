## 接口（前缀 `/api/v1/rider-salary`，权限 `rs:period:*`，站点范围过滤）
- GET `/periods` 分页：筛选 site_id/rider_id/status/年月；每行附：骑手数、payroll 数、stale 数、应发合计、实发合计、kind 分布。
- POST `/periods/generate` body `{site_id, month:'YYYY-MM'}`：按站点周期配置生成该月覆盖的周期实例（半月结 2 个、月结 1 个、自定义按 anchor）；同时为有 `settle_cycle_override` 的骑手生成 rider 级周期；已存在则跳过；返回生成清单。
- GET `/periods/{id}`：周期详情 + 该周期全部 payroll 摘要（含 reversal/supplement 链）。
- POST `/periods/{id}/calculate` body `{rider_ids?: [int]}`：status ∈ {open, reopened} 才可；调用 D3 `calculate_period`；站点级周期算薪时跳过有 rider 级周期的骑手；同步执行（骑手 ≤ 200）否则 BackgroundTasks；返回 `{calculated, warnings}`。
- POST `/periods/{id}/lock` body `{reason}`（必填）：前置：无 stale 的 draft payroll（否则 400「存在需重算的薪资结果：工号 A001、A002…，请先重算」）；动作：`rs_order`/`rs_adjustment`（biz_date 在区间内、同 site、若 rider 级则同 rider）`is_locked=True`；draft payroll → finalized；引用的 plan_version `is_used=True`；period → locked；审计。
- POST `/periods/{id}/mark-paid` body `{reason?}`：locked → paid；payroll finalized → paid；审计（description 必含「已标记发薪，不涉及实际打款」）。
- POST `/periods/{id}/reverse` body `{reason}`（必填）：locked/paid → reopened；对每个 finalized/paid 且未 reversed 的 payroll 调 `create_reversal`；解除区间内 `is_locked`；审计 description 列出反冲单数量与金额合计。
- GET `/periods/{id}/export` → xlsx（`write_workbook`）：Sheet1「薪资汇总」：工号、姓名、站点、周期、单据类型(正常/反冲/补发)、状态、单量、有效单量、逐单合计、按日合计、周期项合计、手工奖、手工惩、应发、代扣、预支抵扣、实发、计算时间；Sheet2「薪资明细」：工号、姓名、日期、阶段、方案、科目、订单号、金额、是否进应发、来源、计算过程（trace 摘要成一行中文）；Sheet3「奖惩记录」；Sheet4「净额对照」（每骑手：原单 / 反冲 / 补发 / 净差）。文件名 `薪资导出_{站点}_{起}_{止}.xlsx`（Content-Disposition 处理中文文件名 RFC 5987）。审计「导出」。
- GET `/periods/for-date?site_id&rider_id?&date` → 返回覆盖该日的周期（无则按配置计算区间并返回 `exists=false`），供前端与日历使用。

## 服务层要求
- `period_service.get_or_create_period(db, site_id, rider_id | None, any_date) -> SettlePeriod`：供 D3 算薪与 D6 预估共用；rider 有覆盖配置时返回 rider 级。
