## 接口清单（前缀 `/api/v1/rider-salary`；全部 `DependsJwtAuth + DependsRBAC + RequestPermission('rs:...')`，权限码见骨架说明；列表接口统一 FBA 分页；站点范围用 `get_visible_site_ids` 过滤并对写操作 `assert_site_visible`）

### 站点 `/sites`
- GET `/sites` 分页，筛选 name/code/status；GET `/sites/all` 下拉用（不分页，仅可见站点）；GET `/sites/{id}`；POST；PUT `/sites/{id}`；DELETE `/sites/{id}`（有骑手引用 → 拒绝「该站点下仍有骑手，无法删除」）。
- GET `/sites/{id}/managers` 返回 `[{user_id, username, nickname, role}]`（联 sys_user，`deleted=0`）；PUT `/sites/{id}/managers` 全量覆盖 `[{user_id, role}]`，owner 至多 1 个。
- 修改周期配置（settle_cycle/cycle_config）时：若该站点已存在 `locked/paid` 周期，允许改但审计写明「仅影响未来周期」；不回溯改已生成周期。

### 骑手 `/riders`
- GET 分页（筛选 site_id/status/employ_type/关键字 工号或姓名）；GET `/riders/{id}`（含 site 名称、当前绑定方案短名、账号状态）；POST（校验工号唯一、站点可见；同时写入首条用工类型历史 start_date=hire_date）；PUT；DELETE（存在订单/薪资 → 拒绝「该骑手已有业务数据，请改为离职」）。
- PUT `/riders/{id}/leave` 离职：body `leave_date, reason`；status=离职；关闭用工类型历史 end_date。
- 用工类型历史：GET/POST/PUT/DELETE `/riders/{id}/employ-history`；区间不重叠校验，写后 `mark_stale`。
- 方案绑定：GET/POST/PUT/DELETE `/riders/{id}/bindings`；校验：plan_version 状态必须 `active`；override 之间不重叠、default 之间不重叠；end ≥ start；成功后把 `rs_plan_version.is_used=True`（首次绑定即视为使用）；写后 `mark_stale`；受锁账约束：绑定区间与 locked/paid 周期重叠 → 拒绝。
- GET `/riders/{id}/effective-plans?start&end` 返回按日解析后的 `[{start,end,plan_version_id,plan_short_name,plan_color}]`（合并连续区间）——**这是日历色带与算薪共用的解析函数**，请实现为 `service/rider_service.py::resolve_effective_plans(db, rider_id, start, end) -> list[Segment]`（Segment 数据类：plan_version_id | None, start, end），无方案区间也返回（plan_version_id=None）。
- 账号：POST `/riders/{id}/open-account` body `{password?: str}`（默认手机后 6 位，无手机则 `Rider@123456`）：用 FBA 用户 CRUD 创建 sys_user（username=工号、nickname=姓名、phone、`is_staff=False`、`is_superuser=False`、status=1），绑定角色「骑手」（按 name 查 sys_role），回写 `rider.user_id`；已有账号 → 拒绝。POST `/riders/{id}/reset-password`、POST `/riders/{id}/disable-account`（sys_user.status=0）、POST `/riders/{id}/enable-account`。以上写审计且 reason 必填（开通/停用）。

### 科目 `/subjects`
- GET 分页 + GET `/subjects/all`（下拉，含 direction/fee_mode/fixed_amount/include_in_gross）；POST/PUT/DELETE。
- DELETE：`is_builtin` → 拒绝「系统内置科目不可删除，可停用」；被 `rs_adjustment` 或 `rs_plan_item` 引用 → 拒绝「科目已被引用（奖惩记录 N 条、方案项 M 条），无法删除」。
- PUT 对内置科目允许改名称/定额/状态，不允许改 code/direction/include_in_gross。

### 奖惩记录 `/adjustments`
- GET 分页（筛选 site_id/rider_id/日期范围/subject_id/方向）；返回含骑手工号姓名、科目名、方向、signed_amount、是否锁账。
- POST 单条、POST `/adjustments/batch` 批量（同一事务，任一失败整批失败并返回行号+中文原因）；PUT；DELETE。
- 校验：骑手在职且属可见站点；科目启用且适用范围匹配（scope_sites/scope_employ_types，按 biz_date 当日用工类型）；amount>0（科目 code=`PREV_PERIOD_ADJ` 上期补差允许负数）；remark 必填；`assert_not_locked`；写后 `mark_stale`；PUT/DELETE 的 reason 必填并写 before/after 审计。
- 「按周期入账」科目：biz_date 可任意，服务层不改动，仅提示。

### 日标记 `/day-flags`
- GET `/day-flags?site_id&month=YYYY-MM` 返回当月每日标记；PUT `/day-flags` body `{site_id, days:[{biz_date, bad_weather, high_temp, promo, remark}]}` upsert；受锁账约束（逐日 `assert_not_locked`）；写后 `mark_stale`（该站点全部在职骑手、涉及日期范围）。

### 站点公告 `/notices`
- CRUD + 发布/下线（status 流转）；`site_id` 可空=全部站点；负责人只能操作本站点公告。

### 操作日志 `/audit-logs`
- GET 分页，筛选 module/action/operator/日期范围/target_type/关键字；按时间倒序。只读。
