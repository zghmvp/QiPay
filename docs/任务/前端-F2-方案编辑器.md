# 任务 F2 · 前端薪资方案：列表、版本、方案编辑器（条件/公式拼装）、试算、回退

先读 `docs/任务/前端-F0-通用约定.md`；再读纲要 §2、§4.5，产品方案第 3 章（编辑器交互）与第 6 章（回退弹窗文案）。后端契约以 `api/v1/plan.py`、`api/v1/engine.py`、`schema/{plan,plan_version,plan_item,engine,trial,rollback}.py` 为准。复用 F1 的 constants/components/utils（若 F1 尚未完成对应组件，先在本模块 components 下实现，命名一致，后续合并）。

## 你负责
- `api/plan.ts`、`api/engine.ts`、`types/plan.ts`、`types/engine.ts`
- `views/plan/index.vue`（方案列表 → 版本列表）、`views/plan/editor.vue`（路由 `/rider-salary/plan/editor/:versionId`，核对 init.sql 中的 path/component）
- `views/plan/components/`：`ConditionBuilder.vue`、`FormulaBuilder.vue`、`LadderEditor.vue`、`ExpressionBuilder.vue`、`PlanItemTable.vue`、`TrialPanel.vue`、`RollbackModal.vue`、`VersionStatusTag.vue`

## 1. 方案列表页 `views/plan/index.vue`
- 左：方案卡片/列表（编码/名称/短名/颜色块/说明/版本数/启用版本数）；新增/编辑方案抽屉（颜色用 `a-color-picker` 或预设 12 色）。
- 右：所选方案的版本表格（版本号/状态 Tag/模式标签/是否已使用/试算状态/创建时间/启用时间）；操作按钮按状态与权限显示：编辑（draft 且未使用 → 进编辑器；否则只读进编辑器）、试算、启用（要求 trial 通过且 hash 匹配，否则按钮 tooltip 提示）、停用（ReasonModal）、复制为新版本、删除（仅 draft 未使用）、回退（仅 `rs:plan:rollback` 且用户 is_superuser，走 RollbackModal）。
- 新建版本按钮 → 创建 draft 后跳编辑器。

## 2. 方案编辑器 `views/plan/editor.vue`
布局：顶部信息条（方案名/版本号/状态/模式标签选择/是否已使用/试算状态）；主体左侧 `PlanItemTable`（按阶段分组：逐单/按日/按周期，可拖拽或上下箭头调整 sort_order，行显示 名称/科目/条件摘要(编译后表达式)/公式摘要/启用开关），右侧为选中项的编辑面板（名称、科目下拉、阶段、`ConditionBuilder`、`FormulaBuilder`、备注）；底部固定操作栏：保存 items（`PUT /plan-versions/{id}/items`）、试算、启用、返回。已使用/非 draft 版本 → 全部只读。

### ConditionBuilder
- 数据结构 = 纲要 §2.2 JSON；顶层逻辑 且/或 切换；条件行：字段下拉（来自 `GET /engine/fields` 并按当前 stage 过滤）→ 运算符下拉（来自 `GET /engine/operators` 按字段类型）→ 值输入按类型渲染：number→`a-input-number`；time→`a-time-picker`(HH:mm)，「在时段内」两个；enum→下拉/多选；bool→是/否 Switch；date→日期；区间→两个输入。支持「添加条件组」嵌套一层。
- 底部实时显示后端 `POST /engine/validate` 返回的 `condition_expr` 中文表达式与错误（防抖 500ms）。

### FormulaBuilder
- 模板 Tabs：固定金额 / 字段乘单价 / 阶梯 / 表达式（结构来自 `GET /engine/formula-templates`）。
- 阶梯用 `LadderEditor`：字段下拉、模式(全量落档/分段累进)、计价(按单价/固定金额)、档位可编辑表格（下限/上限/值，最后一档上限可为空=无上限，自动衔接上一档上限，前端校验连续），右侧小示例：输入一个值实时显示计算结果（调用 `/engine/evaluate-sample`）。
- 表达式用 `ExpressionBuilder`：可点选插入的「字段 chip」「函数 chip」「运算符按钮」「数字输入」，生成的表达式在只读框显示；允许高级用户直接编辑文本框但提交前必须通过 validate。
- 快捷模板按钮「底薪分摊」自动生成表达式。
- 底部同样显示 `formula_expr` 与 validate 错误。

### TrialPanel（抽屉）
- 输入：站点 → 骑手（RiderSelect）→ 日期范围（默认上个自然月）；「开始试算」→ `POST /plan-versions/{id}/trial`。
- 输出：汇总卡片（单量/逐单/按日/周期项/手工奖/手工惩/应发/代扣/实发）；Tabs：逐单明细（表格，行展开显示每项 calc_trace：条件、条件结果、公式、变量、结果）、按日汇总、周期项、警告。试算成功后编辑器信息条显示「试算通过 ✓」；items 再次保存后变为「需重新试算」。

### RollbackModal
- 打开先 `GET /rollback-preview`，列出全部后果（受影响绑定、draft/finalized/paid 结果数、反冲单数、解绑骑手清单）；若 `has_paid`，顶部红色 `a-alert`：「该方案已执行发薪操作，回退将产生财务影响」；必填 reason；输入框必须键入「确认回退」才可点确定；确定后 `POST /rollback`，成功提示并跳转到新复制的 draft 编辑器。

## 验收
- F0 通则；截图：编辑器整体、ConditionBuilder 含嵌套组、LadderEditor、TrialPanel 逐单 trace 展开、RollbackModal（可用 draft 版本预览）。
- 走通：新建方案 → 新建版本 → 添加 4 项（逐单夜间加价固定金额 2 元、逐单距离阶梯、周期底薪固定金额、周期保底表达式）→ 保存 → 试算（需有骑手与订单数据；若无，用 D3/D4 造的数据）→ 启用 → 在骑手页绑定后再次进入编辑器确认只读。
