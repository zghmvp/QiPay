## 1. 绝对禁区
1. **禁止修改 FBA 框架代码**：
   - 后端：`fastapi-best-architecture/` 下除 `backend/plugin/rider_salary/**` 之外的任何文件（含 `backend/core/conf.py`、`backend/.env`、`backend/app/**`、`backend/common/**`、`backend/plugin/*.py`、`backend/sql/**`、alembic 目录等）。
   - 前端：`fastapi-best-architecture-ui/` 下除 `apps/web-antdv-next/src/plugins/rider-salary/**` 之外的任何文件（含路由注册、布局、adapter、locales、preferences、package.json）。
   - 文档目录 `fastapi_best_architecture_docs/` 只读。
   - 例外说明：`fastapi-best-architecture/backend/.env` 是环境配置文件（非源码），允许追加 `CORS_ALLOWED_ORIGINS` 等运行配置；`QiPay/rider-h5/` 是我们自己的独立 H5 应用，可自由新增文件与 npm 依赖（用 pnpm）。
2. 如果不改框架就无法实现某个需求：**立即停止该项**，在最终回复中以「⚠️ 需用户授权的框架修改申请」为题写明：要改哪个文件、为什么、影响范围、有没有插件侧替代方案。其余不受影响的任务继续完成。
3. 不做 git add/commit/push。
4. 不删除、不重建数据库中的 FBA 系统表；插件表可用 `sql/postgresql/destroy.sql` 重建。

## 2. 语言约定
- 一切人可见文本全中文：接口 `summary`/`description`、Pydantic 字段 `description`、SQL `COMMENT`、异常 `msg`、日志、导出表头、前端界面文字、校验提示。**前端不使用 `$t()` 与 langs 目录，直接写中文字面量。**
- 代码标识符英文 snake_case（Python）/ camelCase（TS）；表前缀 `rs_`；权限码前缀 `rs:`。
- 公式引擎变量名、运算符、函数名使用中文（见纲要 §2）。
- 注释与 docstring 用中文。

## 3. 第三方优先
- 能用库就不手写：表达式求值 `simpleeval`、Excel `openpyxl`、节假日 `chinese-calendar`、分页 `fastapi-pagination`（FBA 已集成）、CRUD `sqlalchemy-crud-plus`（FBA 已集成）。新增依赖写入 `backend/plugin/rider_salary/requirements.txt`，并用 `uv pip install -r` 安装到项目 `.venv`（不改 pyproject.toml）。
- 管理后台前端优先用 Antdv Next 组件与 FBA 已封装的 `useVbenForm` / `useVbenVxeGrid` / `useVbenModal` / `useVbenDrawer`、已注册的 echarts；需要给 `web-antdv-next` 新增 npm 依赖时，**先在最终回复中申请**（因为需要改 package.json），不要擅自安装。
- 骑手 H5 独立应用 `QiPay/rider-h5` 使用 Vue 3 + Vite + Vant 4 + axios + dayjs + pinia（可按需精简），依赖自行安装。

## 4. FBA 规范遵循
- 分层：`api/` 只做路由与参数校验；`service/` 业务逻辑与异常；`crud/` 继承 `CRUDPlus`；`schema/` 继承 `SchemaBase`；`model/` 继承 FBA `Base`，所有模型在 `model/__init__.py` 导入。
- 响应统一用 `response_base.success(data=...)`；分页用 FBA 的 `DependsPagination` + `paging_data`。
- 认证 `DependsJwtAuth`；权限 `DependsRBAC` + `RequestPermission('rs:xxx:yyy')`，写法与 FBA admin 应用一致（以《后端架构调研》为准）。
- 异常用 FBA `errors.py` 中的类并传中文 `msg`。
- 时间用 FBA `timezone` 工具；金额用 `Decimal`。
- 编码风格遵循 FBA ruff 配置（单引号、行宽等，以 `pyproject.toml [tool.ruff]` 为准）；写完运行 `uv run ruff check backend/plugin/rider_salary` 与 `uv run ruff format backend/plugin/rider_salary`（若项目提供）。

## 5. 审计日志（所有写操作必做）
- 调用插件内统一服务 `audit_service.record(module, action, target_type, target_id, target_label, reason, before, after, description)`（由骨架任务提供；若尚不存在，按纲要 §1.19 创建）。
- `description` 模板：「{操作人} 于 {时间} 对 {对象} 执行了 {动作}，原因：{原因}」；无原因时省略「，原因：…」。
- 纲要 §1.19 列出的动作 `reason` 必填，缺失时抛中文校验错误「请填写操作原因」。

## 6. 重算标记（所有影响算薪的数据写操作必做）
对 `rs_order` / `rs_adjustment` / `rs_rider_plan_binding` / `rs_day_flag` / `rs_rider_employ_history` 的写操作后调用 `recalc_service.mark_stale(rider_ids, date_from, date_to)`（由算薪任务提供；若尚不存在，先写一个占位函数并在回复中注明）。

## 7. 锁账校验（所有影响算薪的数据写操作必做）
写操作前检查目标 (site/rider, biz_date) 所属周期状态；`locked`/`paid` → 抛「该日期所属结算周期已锁账，禁止修改，请走反冲补发流程」。

- 多个子角色并行开发同一插件时，**只改任务分配给你的文件/模块**；需要别人模块的函数而对方尚未完成时，按纲要中的签名先写最小占位并在回复中标注。
- 不要重构、不要「顺手优化」他人代码；发现问题写进回复的「需要架构师决策的问题」。
